# 게임 시스템 명세

같은 상황에서 같은 규칙을 해석할 수 있을 만큼 구체적인 명세를 만든다. 구현 코드나 모든 장르에 통하는 거대 스키마를 만들지 않는다.

## 시작과 소유권

- 먼저 [공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)을 읽는다.
- `00-brief.md`, `02-concept.md`, 관련 조사 근거와 기존 규칙·수치 정본을 읽는다.
- 출력은 프로젝트 기획 경로의 `03-systems.md`다. 다른 단계 문서와 `workflow.json`은 수정하지 않는다.
- 컨셉이 없으면 사용자 자료에서 목적과 루프를 식별하고 전제가 부족한 명세는 조건부 초안으로 표시한다.
- 핵심 규칙을 바꾸는 누락 정보만 질문하고, 의존하지 않는 규칙은 계속 명세한다.
- 기존 코드·CSV·JSON이 수치의 정본이면 해당 파일과 버전을 참조한다. 별도의 경쟁 정본을 만들지 않는다.

## 규칙을 구체화하기

1. 핵심 루프에 필요한 시스템을 식별하고 각각 안정적인 `SYS-*` ID와 책임을 부여한다.
2. 시스템이 어떤 컨셉 `C-*`와 결정 `D-*`를 실현하는지 연결한다.
3. 입력 또는 사건, 이전 상태, 발동 조건, 상태 변화와 효과, 플레이어 피드백을 명시한다.
4. 조건의 평가 시점과 순서를 정한다. 동시 입력·충돌·중복 발동의 우선순위가 결과에 영향을 주면 적는다.
5. 정상 예시와 경계 예시로 규칙을 확인한다. 예시가 본문 규칙과 다른 예외를 몰래 만들지 않게 한다.

## 게임에 맞는 내용

- 적·스킬·아이템·자원·퍼즐 오브젝트 등 실제 존재하는 개념만 명세한다. 모든 게임에 적의 공통 필드를 강제하지 않는다.
- 상태가 중요한 시스템은 진입·유지·이탈 조건과 허용되지 않는 전이를 설명한다.
- 시간, 자원, 사용 횟수, 확률이 있으면 비용·회복·상한·하한과 경계에서의 동작을 정한다.
- 타이밍과 공간이 규칙의 핵심이면 단위, 좌표·거리 기준, 판정 시점과 필요한 허용오차를 적는다.
- 조합·상쇄·카운터가 재미에 영향을 주면 성립 조건과 예상 결과를 적는다. 의미 없는 전체 조합표는 만들지 않는다.
- 피드백에는 플레이어가 알 수 있는 정보와 숨겨지는 정보를 구분한다. 결과를 오해하게 만드는 정보 누락을 점검한다.
- 취소·중단·실패·재시도·저장 복구가 관련되면 남는 상태와 초기화되는 상태를 정의한다.
- 접근성이나 입력 장치 차이가 규칙에 영향을 주면 동등한 행동을 수행할 조건을 남긴다.

## 수치와 정본

- 수치는 값, 단위, 적용 범위, 근거 또는 산정식, 상태를 함께 기록한다.
- 목표·가정·계산·실측을 구분한다. 아직 모르는 값은 미정이며 0으로 채우지 않는다.
- 계산값은 사용한 입력·공식·모델 버전을 기록하고, 반올림이나 확률 분모가 의미를 바꾸면 명시한다.
- 밸런스 초안의 숫자를 검증된 숫자로 표현하지 않는다. 어떤 관찰이 값을 바꿀지 연결한다.
- 같은 변수가 여러 곳에 필요하면 소유 항목을 참조한다. 복사한 값이 충돌하면 권위 있는 근거와 버전을 먼저 확인한다.
- 수치가 기존 컨셉·사용자 결정과 충돌하면 영향과 수정 선택지를 남기고 상위 결정을 임의로 대체하지 않는다.

## 산출물과 검수

- `03-systems.md`에 시스템 책임, 규칙, 상태·콘텐츠 명세, 수치 근거, 예외와 주요 상호작용을 담는다.
- 구현자가 판단해야 하는 미정 조건과 검증이 필요한 밸런스 가정을 구분한다.
- 대표 입력을 규칙 끝까지 따라가며 상태·조건·효과·피드백이 빠짐없이 결정되는지 검토한다.
- 자원 부족, 한계값, 동시 효과, 반복 실행 등 실제 규칙에 관련된 경계만 검토한다.
- 단위·용어·ID의 중복과 참조 누락을 확인하고, 예정인 후속 참조는 실제 대상과 구분한다.
- 진행 단계에 시스템 도입 전제, 난도 조절 변수, 금지 조합, 검증할 가정을 전달한다.
- 산출물 경로 / 반영한 결정 ID / 남은 가정·충돌 / 검수 결과 / 다음 단계 입력을 반환한다.
- 이 단계의 완료는 규칙 문서 검수다. 규칙 구현이나 플레이 테스트 완료를 뜻하지 않는다.
