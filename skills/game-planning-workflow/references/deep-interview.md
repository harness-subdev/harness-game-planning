# 보고서 근거 확인과 수정

내용 검수는 핵심 설명의 근거·관계·범위를 대조하고 실제 원문을 고치는 작업이다. [validation](../../game-planning-validation/SKILL.md)이 요청 범위의 검토를 맡고 문제를 소유한 작성자가 수정한다. HTML 표시만 바꿀 때는 현재 내용 검수 결과를 사용한다.

## 입력과 역할

[문서 모드](artifact-contract.md#문서-모드와-원작-레퍼런스-보고서), 사용자 확정 기준·전체 피드백, 보고서 초안, 용어 정본, 원자료·장면 기록과 작성 권한을 전달한다. 자료로 확인 가능한 내용을 먼저 작성하고 미확인 사실은 그 범위로 남긴다. 독립 검토자가 있으면 실제 자료를 읽고 질문·수정 인계를 맡기고, 없으면 작성자가 순차 대조한다. 실제 참여하지 않은 검토자·메시지·문답을 만들어 기록하지 않는다.

## 근거에서 후속 질문으로

핵심 설명을 바꿀 빈틈부터 해당 문장·표·그림·자료 위치를 확인한다. 질문이 앞 답에 의존하면 하나를 확인한 뒤 다음 질문으로 잇는다. 독립 문제는 묶어서 전달할 수 있다. 질문 개수나 인터뷰 형식을 채우기 위해 근거가 충분한 부분을 반복 평가하지 않는다.

작성자는 `확인한 답 또는 미확인 → 직접 근거 위치 → 관찰/자료 설명/추론의 차이 → 반례·조건 → 유지·수정·축소할 문장`을 전달한다. 권장 수정은 제안이며 게임 사실이나 사용자 승인으로 쓰지 않는다. 답을 받았다는 사실보다 원자료가 그 답을 뒷받침하는지를 대조한다.

| 원작 보고서에서 확인할 연결 | 대조할 내용 |
| --- | --- |
| 개요와 범위 | 무엇을 하는 게임인지 → 전체 소개와 상세 대상 → 확인된 종류·목표·진행. 사례 목록을 필수 진행 순서로 만들었는가? |
| 메커니즘과 콘텐츠 | 입력/행동 → 조건·상태 → 결과·화면 피드백. 아웃게임/인게임과 장르별 상세가 실제 게임에 맞는가? |
| 선택과 후속 결과 | 가능한 행동 → 지금 얻거나 감수하는 것 → 다음 행동·자원·진행. 관찰한 결과보다 넓게 단정했는가? |
| 진행·재도전 | 진입·실패·재시작 → 초기화/유지 → 다음 공략·조작. 반복 영상만으로 실제 학습을 확정했는가? |
| 장면 설명과 근거 | 설명 위치 → 관찰 기록·자료 설명·미확인·직접 출처. 캡처가 있으면 시각·행동·전후 변화·UI가 대응하고, 없으면 문서 수준 설명의 근거와 한계가 드러나는가? |
| 설계 특징 | 앞 절의 실제 근거 → 시스템 간 연결. 원작 결론에 새 게임의 제작·QA·시험 제안을 섞었는가? |

목차·상세는 [산출물 계약](artifact-contract.md#원작-보고서의-정형-목차), 장면 취득·문서 수준 설명과 주장 범위는 [research 정본](../../game-planning-research/SKILL.md#실제-플레이-장면과-ui-취득), 문체·기록의 표시 범위는 [용어 정본](game-terminology.md#독자용-문체와-작업-기록의-경계)으로 판단한다.

신작 기획은 요청된 C/D/SYS/P/V에 대해 `경험 가설 → 가능한 선택 → 규칙·진행 → 필요한 시험과 수락 조건 → 판정 가능한 범위`를 추가 대조한다. 새 정책은 원작 근거와 구별하고 실제 구현·사람 시험은 해당 실행 증거가 있을 때 분석한다. 원작 보고서를 이 신작 검토 표로 확장하지 않는다.

## 실제 수정과 인계

1. `문제·영향 위치 | 직접 근거 | 수정 소유자 | 실제 수정 또는 주장 축소 | 재확인 결과·남은 범위`를 기존 검수 기록에 남긴다.
2. 사실·장면·UI 근거 부족은 research에 조사 질문과 필요한 화면을 인계한다. 잘못된 경험·규칙·진행 해석은 해당 작성자에게 수정할 보고서 위치를 전달한다. 확인 불가 사실을 권장 답·새 설계로 채우지 않는다.
3. 작성 권한 안에서 실제 원문을 수정하고 변경 위치·근거를 전달한다. 다른 작성자의 정본은 소유자에게 인계한다. 독립 검수 호출의 권한 밖이면 구체적인 수정안과 미적용 상태를 남기고 수정됐다고 보고하지 않는다.
4. 수정한 파일의 해당 설명과 영향을 받은 참조를 다시 읽는다. 새 근거 없는 재질문·점수 계산이나 고정 횟수의 수정 루프를 만들지 않는다. 남은 근거 없는 단정은 삭제·축소하거나 중요한 미확인으로 바꾼다.
5. 수정된 원문·그림·근거와 검수 결과를 [HTML 스킬](../../front-game-planning-html/SKILL.md)에 전달한다. 표시 데이터·HTML에서 내용이 달라지면 원문 소유자에게, 배치·표시 문제는 HTML 담당에게 반환한다.

## 완료 범위

실제로 수정·대조한 위치와 남은 한계·미실행을 기록하고 요청한 문서를 전달한다. 문서 대조는 원작 내부 구현이나 사람의 재미 검증이 아니다. 해결할 자료가 없는 중요한 질문은 숨기지 않고 해당 설명의 한계로 남긴다. 사용자 확정 선택과 충돌하는 새 제안은 제안으로 유지한다. 내부 문답·수정·검수 이력은 독자용 원작 보고서에 투영하지 않는다.
