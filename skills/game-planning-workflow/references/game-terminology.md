# 게임 기획 용어 참고 사전

이 사전은 초보자와 개발 실무자가 함께 읽는 보고서의 **권장 명칭과 개념 경계**다. 업계 전체의 공식 한국어 표준이 아니다. 공식 자료는 원개념과 작품별 사용례의 근거이며, 한국어 공식 번역의 근거와는 구별한다. 확인일: 2026-10-12.

장르별 정의의 기본 입력과 조회 계약은 [V3 도메인 사전 조회와 보고서 적용](domain-dictionary.md)이다. 이 문서는 프로젝트 명칭·문체 지침과 기존 명칭 예시를 제공한다. 아래 공용 표나 Cuphead 예시를 선택 장르의 조회 결과에 자동 합치지 않는다. V3 본문은 선택 범위만 읽으며 프로젝트 피드백·확정 용어 목록 전체 읽기와 구별한다.

프로젝트 사전에는 실제 사용하는 항목만 선택한다. 기존 사용자 확정 명칭과 작품별 공식 명칭을 먼저 확인하고, 새로운 개념은 근거와 함께 추가한다. 존재하지 않는 성장·전투·경제 시스템을 이 표에서 가져오지 않는다.

## 용어 정본과 명칭 대조

본문을 쓰기 전에 기존 프로젝트 사전·사용자 확정 명칭을 읽고 [V3 조회·용어 선택](domain-dictionary.md)에 따라 장르 이름을 확인한 뒤 필요한 전문어만 선택한다. 기존 프로젝트 사전이 없으면 기획 경로의 `00-glossary.md`에 실제 쓰는 항목만 저장한다. 아래 사전에서 이름만 가져와 해당 게임의 규칙을 추정하지 않는다.

1. 각 항목에 본문 명칭·쉬운 정의·구별할 개념·원어/다른 표기·명칭 상태·근거 위치를 둔다. 짧은 보고서는 짧은 사전이면 된다.
2. 명칭 상태는 공식 표기·설명용 명칭·프로젝트 정의·미정으로 구별한다. 공식 UI·매뉴얼·발표에서 해당 이름을 실제 확인했을 때 공식 표기로 쓴다. 외국어 개념의 확인과 공식 한국어 번역의 확인은 별개다. 공식성 미확인 자료의 이름은 보존하되 그 한계를 적는다.
3. 고유명은 역할과 함께 소개하고 원어는 최초 등장 또는 명칭 대조에서 추적한다. 출처 제목·인용·실제 메뉴 문자열·URL·원자료 ID와 코드 키는 대조에 필요한 표기를 유지한다.
4. 제목·목차·본문·표·캡션·링크 이름·HTML에서 같은 개념은 같은 대표 명칭을 사용한다. 사전에 없는 혼동 용어, 다른 개념을 합친 이름, 정의 후 반복하는 불필요한 영문 약어를 의미로 대조한다. 본문을 먼저 쓴 뒤 일괄 치환하는 것으로 대신하지 않는다.
5. 작성자는 필요한 항목을 보완하며 병렬 작업에서는 사전 담당 한 명에게 변경안을 인계한다. 미정 명칭은 임시 이름과 한계를 적어 독립 작업을 계속한다. 의미가 바뀌면 해당 규칙의 작성자와 참조 문서도 대조한다.
6. HTML만 작업할 때도 기존 사전을 읽는다. 없으면 원문의 명칭을 정리해 저장하고 원문 소유권 밖의 의미 변경은 작성자에게 인계한다. 독자에게 필요한 정의는 본문에서 설명하며, 정의만 담긴 사전은 연결할 수 있다. 피드백·수정 이력이 섞인 작업용 사전은 독자용 링크로 쓰지 않는다.

완료 인계에는 사용한 사전과 남은 용어 충돌을 전달한다. 총괄은 소비한 사전의 실제 해시와 변경 영향을 작업 기록에 남긴다. 사전 대조는 작성·검수 작업이며 렌더러의 자동 동기화 기능이 아니다.

## 독자용 문체와 작업 기록의 경계

게임을 모르는 독자가 한 번에 대상·행동·결과를 이해하도록 핵심을 먼저 설명한다. 쉬운 명사·동사를 사용하고 누가 무엇을 보고 어떤 행동을 하며 무엇이 바뀌는지 쓴다. 뜻이 분명한 제목과 표 항목은 명사로 쓴다. ‘공간 복구’·‘선택 비용’처럼 대상이 숨는 표현은 실제 행동과 결과로 풀어 쓴다.

- 플레이 공간은 스테이지, 성장 수치는 캐릭터 레벨로 구별한다. 보스명·스테이지명·전투 단계·공격명·공격 패턴을 구별하고 이름을 처음 보는 독자에게 역할·종류·목표를 먼저 설명한다.
- 도전·피격·피해·사망·전멸·플레이 중단·재시작·격파·완료를 해당 사건에 맞게 쓴다. 공략 변경과 같은 공략의 조작 조정을 나누고, 변경이나 반복만으로 실제 학습·숙련 향상을 확정하지 않는다.
- 표는 실제 설명 대상별로 나눈다. 서로 다른 캐릭터 상태·카드·보유 장비·선택 장비·진행 기록이나 여러 장비의 이점/제약을 한 셀에 압축하지 않는다. ‘주체·범위’ 같은 추상 열 대신 무엇을 비교하는지 알 수 있는 이름을 쓴다.
- 영상과 UI 설명은 [research의 장면 취득](../../game-planning-research/SKILL.md#실제-플레이-장면과-ui-취득)을 따른다. 중요한 조건·미확인은 해석하는 설명 가까이에 쉽게 남기며, 기능 설명을 내부 검수 절차로 바꾸지 않는다.

원작 보고서의 제목·목차·본문·표·캡션·링크 이름·부록 전체에서 보고서 v3/v4/v5/v6 번호, 이전 작성본 소개, 내부 문답·수정·검수·HTML 생성 이력과 그 기록 링크를 제외한다. 부록으로 옮기는 방식도 사용하지 않는다. 현재의 올바른 게임 내용과 근거를 직접 설명해 이전 작성본 없이 이해할 수 있는 보고서 하나로 완성한다.

자료 ID·해시·원본/최종 파일·취득 실패·제외 이유·수정/재검토는 기존 별도 작업 기록에 보존한다. 자료 소개에는 수집한 공식 참고자료의 제목과 직접 링크를 둔다. 가이드·위키·리뷰·개인 영상은 공식 자료와 구별해 해당 항목의 직접 원자료로 연결한다. 원자료 출처·실제 자료 조사일·권리·중요 관찰 조건·미확인·실제 게임의 패치 차이는 보고서에 유지한다. 파일명에 있는 보고서 번호를 캡션·링크 이름으로 옮기지 않는다.

자료 날짜는 ‘자료 조사일’, ‘화면을 저장한 날짜’처럼 대상을 밝혀 쓴다. ‘취득일을 승계한다’ 같은 관리 문구와 수정 경위는 작업 기록에 남기되 쉬운 표현으로 바꾸면서 실제 날짜나 새 조사 여부를 바꾸지 않는다.

신작 문서에는 요청된 설계·제작/시험 인계와 상태를 그 계약에 따라 표시한다. 원작 보고서의 독자용 경계를 적용해 신작의 유효한 수락 조건·미실행 상태를 삭제하지 않는다.

## 명칭을 고르는 기준

- **관용어 + 쉬운 정의:** 보스·패링·스킬·스테이지를 유지하고 기능을 짧게 설명한다. 낯선 직역어를 새로 만들지 않는다.
- **명칭 + 구별되는 범위:** 플레이 공간은 `스테이지`로 쓰고 `캐릭터 레벨`·`지역`·`전투 단계`와 구별한다. `공격 패턴/전투 단계`, `난이도/난이도 설정`도 나눈다. 원자료의 level 표기·공식 이름·코드 키는 보존한다.
- **역할 + 고유명:** `플레이어 캐릭터 — 컵헤드·머그맨`, `보스 — 캐그니 카네이션`처럼 역할을 알린다. 확인되지 않은 한글 표기는 설명용 표기이며 공식 번역으로 표시하지 않는다.
- **명칭 상태 + 확인 근거:** 매뉴얼에 나온 이름을 보존하는 것과 그 매뉴얼의 공식 여부를 확인하는 것은 별개다. 공식임을 확인할 수 없는 제공 매뉴얼의 이름은 프로젝트 정의 또는 설명용 명칭으로 기록하고 공식 여부 미확인을 표시한다.
- **개념 + 작품별 규칙:** 필살기·패링·세션의 명칭만으로 피해량·성공 효과·측정 기준을 추정하지 않는다. 정의와 게임 규칙은 각각의 근거로 확인한다.

| 대표 명칭 | 쉬운 정의 | 원어·다른 표기 | 구별할 개념 |

| 플레이어 | 게임을 플레이하며 선택하고 조작하는 사람. | player | 게임 속 캐릭터와 구별한다. 자동 플레이 주체는 봇·에이전트라고 명시한다. |

| NPC | 플레이어가 직접 조작하지 않고 게임이 행동을 결정하는 캐릭터. | non-player character | 상인·동료·적을 포함할 수 있다. 비전투 인물만을 뜻하지 않는다. |
| 보스 | 주요 도전으로 배치된 적 또는 적 집단. | boss | 반드시 스테이지 마지막에 있거나 하나의 몸체일 필요는 없다. |

## 규칙과 행동, 결과 전달

참고: [Roblox의 코어 루프](https://create.roblox.com/docs/production/game-design/core-loops), [Epic의 행동·상태·수치·시청각 표현 구별](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-the-unreal-engine-gameplay-ability-system), [입력과 행동 연결](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine), [Microsoft의 시청각 정보 전달](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103). 아래 한국어 구별은 보고서 편집용이며 엔진 구현의 분류와 일치할 필요는 없다.

| 대표 명칭 | 쉬운 정의 | 원어·다른 표기 | 구별할 개념 |
| --- | --- | --- | --- |
| 게임 규칙 | 무엇을 할 수 있고 어떤 조건에서 어떤 결과가 생기는지 정한 약속. | rules, mechanics | 장르·분위기·세계관 전체와 같지 않다. 개별 작동 원리를 강조하면 메커니즘을 정의해 사용한다. |
| 핵심 플레이 반복 구조 | 주요 행동과 결과가 다음 행동으로 이어져 반복되는 구조. | core gameplay loop, 코어 루프, 플레이 루프 | 프로그램의 프레임 처리 루프와 다르다. 보상·성장이 모든 게임의 필수 요소는 아니다. |
| 조작 | 키·버튼·터치 등으로 게임에 명령을 보내는 방법. | controls | 실제 입력값과 실행된 행동을 구별한다. |
| 입력 | 실제 버튼 눌림·방향·터치 등 게임이 받은 신호. | input | 입력을 받았다고 행동이 반드시 실행되지는 않는다. |
| 행동 | 이동·점프·공격·대화처럼 수행하는 일. | action | 요청 입력, 현재 상태, 행동 결과를 나누어 쓴다. |
| 상태 | 현재 조건을 나타내는 정보. | state, status | 공중·기절 같은 캐릭터 상태, 게임 진행 상태, 문서 작업 상태의 주체를 명시한다. |
| 능력치 | 체력·공격력·이동 속도처럼 능력이나 현재 조건을 나타내는 수치. | stat, attribute | 할 수 있는 일인 능력과 다르다. 수치형 자원과 겹칠 수 있지만 모든 능력치가 소모 자원은 아니다. |
| 체력 | 현재 버틸 수 있는 정도를 나타내는 게임 수치. | health, HP | 최대 체력·현재 체력·피해량을 구별한다. 0의 결과는 해당 게임 규칙을 확인한다. |
| 자원 | 획득·보유·소비·회복하며 선택에 영향을 주는 값이나 물품. | resource | 탄약·마나·동전 등 실제 항목을 적는다. 제작 인력·예산·아트 자산과 구별한다. |
| 플레이어 피드백 | 행동·상태·결과를 플레이어에게 알려주는 화면·소리·진동 등의 반응. | gameplay feedback, cues | 검토자의 의견과 다르다. 체력 감소와 그 감소를 알리는 표시도 구별한다. |

## Cuphead: 보고서용 명칭의 예

다음은 피드백에서 정한 기능 중심 명칭의 **작품별 예시**다. 공식 한국어 UI 번역을 확인한 표가 아니다. 소비량·장착 조건·대상별 효과는 해당 프로젝트의 원자료로 따로 확인한다.

공식 확인 근거: [개발사 패치 1.1.3의 Super·Charm](https://studiomdhr.com/cupdate-patch-notes-v1-1-3/), [개발사 Steam 발표의 Super Art·Astral Cookie charm](https://store.steampowered.com/oldnews/?appgroupname=Cuphead&appids=268910&feed=steam_community_announcements), [게임이 제공한 Steam 도전과제 원문](https://steamcommunity.com/stats/268910/achievements/), [공식 홈페이지의 캐릭터 이름](https://cupheadgame.com/). 도전과제는 Extra Special move·Super Art·Expert·Normal이라는 원어를 확인하는 근거이며, 메뉴의 EX·Simple·Regular 철자나 모든 전투 수치를 입증하지 않는다.

| 본문 명칭 | 쉬운 정의·원어 대조 | 명칭 상태·주의점 |
| --- | --- | --- |
| 보조 장비 | 장착해 효과를 얻는 장비 분류. Charm에 대응한다. | 설명용 명칭. 모든 효과를 단순 능력치 증가로 좁히지 않는다. 다른 게임의 Charm에 자동 적용하지 않는다. |
| 무기별 특수 공격 | 현재 무기에 따라 달라지는 추가 공격. EX에 대응하는 보고서 명칭이다. | 설명용 명칭. Extra Special move 원개념은 공식 도전과제에서 확인했다. EX 축약과 실제 사용 조건은 프로젝트 근거를 확인한다. |
| 필살기 | 장착한 Super / Super Art를 사용하는 기술 분류. | 설명용 명칭. **모든 종류가 공격은 아니다.** 필살기라는 이름만으로 즉사·최강 공격·소비량을 추정하지 않는다. |
| 난이도 설정 — 간소화 / 보통 / 고난도 | 제공된 Simple / Regular / Expert를 구별하는 기능 중심 표기. | 설명용 명칭. 이 조사에서 Simple·Regular 메뉴와 공식 한글 번역은 직접 확인하지 못했다. 도전과제 원문의 Normal과 메뉴 Regular를 대조 없이 일괄 치환하지 않는다. |
| 플레이어 캐릭터 — 컵헤드·머그맨 | Cuphead / Mugman의 역할과 한글 표기. | 설명용 한글 표기. 공식 영문 이름 확인과 공식 한글 번역 확인은 별개다. |
| 보조 장비 — 대시 방어 | Smoke Bomb의 기능을 드러내는 명칭. | 제공 자료에 근거한 설명용 명칭. 효과의 실제 범위를 해당 자료와 대조하며 상시 무적으로 확대하지 않는다. |

예시 정의는 컵헤드 프로젝트의 시작점이다. 다른 장르의 Special Move가 공식적으로 필살기라면 그 이름과 기능을 보존한다. 새 게임의 EX·Super·Charm이 위와 같다고 추정하지 않는다.

## 프로젝트 사전의 최소 형식

`00-glossary.md` 또는 기존 용어 정본에 항목별로 다음을 기록한다. 원어가 없으면 ‘없음’, 근거가 부족하면 ‘미정’과 임시 명칭을 적는다. 표가 너무 넓으면 항목별 짧은 목록으로 쓴다.

- **본문 명칭:** 무기별 특수 공격.
- **쉬운 정의:** 현재 무기에 따라 달라지는 추가 공격.
- **구별:** 장착한 별도 기술인 필살기, 장착 효과를 주는 보조 장비와 구별.
- **원어·다른 표기:** EX.
- **명칭 상태:** 설명용 명칭. 공식 한국어 메뉴명 미확인.
- **근거:** 사용자 제공 자료의 EX 설명 또는 실제 확인한 매뉴얼 위치. 확인되지 않은 소비량은 채우지 않음.
- **V3를 사용한 항목:** 사전 node ID/key·ref·본문 사용 위치. 주 범위/별도 참조의 조회 선택과 사전 경로·해시는 기존 작업 기록에서 추적한다. 사전에 없는 EX 같은 작품별 명칭은 실제 자료를 근거로 하며 임의의 V3 ID를 붙이지 않는다.

## 보고서에서 확인할 예

대표 명칭을 정했으면 규칙 제목도 `무기별 특수 공격의 사용 조건`으로 쓴다. EX는 최초 원어 병기·원자료 대조에서 추적한다. `객체 / 중요한 속성 / 바뀌는 사건 / 독자가 확인할 피드백` 대신 실제 내용에 맞춰 `전투 대상 / 체력·보유 카드 / 상태를 바꾸는 행동·조건 / 화면·소리 반응`을 선택한다. 서로 다른 정보를 한 칸에 묶어야 한다는 고정 표 형식은 아니다.

공식 표기인지 확인하지 않은 기능명을 공식 번역으로 선언하는 것, 패링을 모든 공격을 막는 행동으로 쓰는 것, 클리어를 계약 획득·콘텐츠 해금과 같은 뜻으로 쓰는 것은 의미 검수에서 구별한다. 원자료의 공백은 번역이나 사전 정의로 메우지 않는다.
