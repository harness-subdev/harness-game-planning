# V3 도메인 사전 조회와 보고서 적용

보고서·기획 작성 전에 [게임 도메인 사전 V3](game-domain-dictionary-v3.md)의 첫 `<!-- game-domain-metadata … -->` 주석 안 JSON을 읽는다. `schema=game-domain-dictionary-query/1`과 실제 `nodes`를 확인한다. 본문 전체를 모델 문맥에 넣지 않고 필요한 노드의 표 행만 읽는다. 목차 후보·키워드 유사성으로 노드를 만들어 내지 않는다.

## 사전 위치와 유지

기본 입력은 이 스킬의 `references/game-domain-dictionary-v3.md`다. 사용자 확정 V3를 바이트 그대로 포함한 읽기 전용 참고 자료이며 프로젝트의 `00-glossary.md`와 구별한다. 스킬 폴더와 함께 이동·배포하며 세션 출력 폴더의 절대 경로에 의존하지 않는다. 이 자료를 보고서 작업 중 수정하거나 재집필하지 않는다.

사용자가 다른 확정 사전 경로를 지정하면 그 파일을 우선하고 같은 메타데이터 계약을 확인한다. 기본 파일이 없거나 계약이 맞지 않으면 정확한 제한을 기록하고 기존 프로젝트 명칭·확인된 자료로 독립 작업을 계속한다. V3 조회 완료로 처리하거나 구 사전을 자동 대체했다고 기록하지 않는다. 사전 갱신은 별도 요청에서 확정 원본을 그대로 교체하고 조회 검사를 다시 실행하는 작업이다.

## 범위 선택

1. 대상의 실제 조작·목표·진행 또는 신작의 확정/제안 조건을 읽고 `kind=genre/subtype`의 ID·title과 대응시킨다. `genre_names`의 이름 정의와 구별 기준으로 일치 여부를 확인한다. 기능·행동·공용 개념·`term_group`을 새로운 하위 장르로 만들지 않는다. 분류 근거가 부족하면 후보·미확인으로 기록한다.
2. 충분히 구체적인 노드를 선택한다. 복합 장르는 필요한 장르·하위 유형을 각각 명시하고 선택 이유를 남긴다. 상위 장르 전체가 조사 대상이면 그 노드를 선택하며, 하위 유형만 필요하면 그 노드를 선택한다.
3. 기본 범위는 선택 노드와 `parent` 역조회로 산출한 모든 자손이다. `parent`로 부모를 회수하거나 `references`를 따라가지 않는다. 각 노드의 직접 범위는 `node.anchor`부터 **본문 순서의 다음 등록 node.anchor 직전**까지이며 마지막 노드는 EOF까지다. 호환 앵커·Markdown 제목 깊이는 경계가 아니다.
4. 조회는 그 범위의 `key/value` 표 데이터 행만 반환한다. `all`은 전체 선택 행, `genre_names`는 각 노드의 `genre_name_keys`, `terms`는 이를 제외한 전문어다. 집필에는 `terms`를 사용하고 범위를 더 좁힐 때 `scope=direct`를 쓴다. 동명어는 `(node ID, key)`로 식별한다.
5. 부모·공용·다른 장르의 개념이 필요하면 사용 목적·별도 노드·필요한 key를 명시해 **별도 조회**한다. `references`는 별도 참조의 단서이고 자동 합류 규칙이 아니다. 참조 대상의 직접 범위에서 필요한 항목만 읽는다. 직접 전문어가 없으면 빈 결과를 유지하고 필요한 별도 참조 또는 프로젝트 정의의 근거를 기록한다.

## 조회 명령

이 스킬 디렉터리를 기준으로 실행하거나 실제 설치 경로로 script 경로를 해석한다. Python 표준 라이브러리만 사용하며 실행 중 사전을 변경하지 않는다. 도구는 파일을 내부에서 읽되 모델에 메타데이터 또는 선택한 행만 출력한다.

```sh
# 먼저 메타데이터만 확인: 실제 노드·이름 키·참조 관계
python3 scripts/query_dictionary.py --list
# 이름을 확인한 뒤 FPS 전문어만 조회
python3 scripts/query_dictionary.py 1.2.1 --mode genre_names
python3 scripts/query_dictionary.py 1.2.1 --mode terms
# 복합 장르의 각 범위는 명시적으로 선택
python3 scripts/query_dictionary.py 1.2.1 1.23.2 --mode terms
# 필요한 공용 개념은 별도 직접 조회
python3 scripts/query_dictionary.py 2.6 --scope direct --mode terms --key '런(run)'
```

`--key`는 선택 범위 안의 정확한 key 필터이며 반복할 수 있다. `--dictionary /absolute/path/dictionary.md`로 사용자 지정 파일을 조회한다. CLI 기본값은 메타데이터와 같이 `all`, 선택 노드+자손이다. 결과는 사전 경로·SHA-256·선택 ID·mode/scope·선택 노드 메타데이터와 원래 여섯 열(`key`, `value`, `구별 기준`, `보고서 예문`, `의미 차이`, `ref`)을 보존한 행이다. 메타데이터/앵커 오류·등록되지 않은 ID·범위에 없는 key는 오류이며 빈 정상 조회로 처리하지 않는다.

## 용어 선택과 집필

- 필요한 행의 `value`·구별 기준·의미 차이를 비교해 설명하는 대상·행동·결과에 맞는 명칭을 고른다. 보고서 예문은 문장 적용의 참고이며 실제 작품의 규칙·수치·관찰 사실이 아니다.
- `ref` 번호가 가리키는 출처가 필요하면 사전의 `3` 노드 직접 범위에서 해당 번호 행만 확인한다. 번호형 출처는 전문어 행이 아니다. 예: `rg '^\[7\] ' references/game-domain-dictionary-v3.md`. 외부 원문을 읽지 않았다면 사전에 기재된 출처를 확인한 범위로 기록한다.
- 선택 항목만 기존 프로젝트 사전/`00-glossary.md`에 기록한다. **본문 명칭·쉬운 정의·구별·원어·명칭 상태·작품 규칙 근거**에 더해 **사전 node ID/key·ref·본문 사용 위치**를 둔다. 사전 경로/해시·주 범위와 별도 참조의 ID/mode/scope/key·선택 이유는 기존 작업 기록에 한 번 남겨 인계한다. 새 경쟁 사전·로그 체계를 만들지 않는다.
- 사용자 확정/작품 공식 명칭을 보존한다. V3와 의미가 다르면 작품별 정의·근거·충돌을 프로젝트 사전에 밝힌다. 신작의 새 규칙은 제안/프로젝트 정의로 기록하고 기존 사전 정의를 변경하지 않는다. 사전에 없는 개념도 실제 근거에 따라 설명용 명칭·프로젝트 정의·미정으로 다룬다.
- 본문에서 처음 사용하는 낯선 말은 쉬운 정의와 실제 대상·행동·결과로 설명한다. 예를 들어 FPS의 반동과 탄퍼짐은 별개이며, 사전 예문의 '연속 발사할수록 위로 밀림'을 모든 작품의 반동 규칙으로 단정하지 않는다. 정확한 발사 변화는 작품 근거 또는 신작의 명시적 설계에서 확인한다.

## 집필 후 의미 검수와 인계

validation은 제목·본문·표·캡션의 실제 사용 문장을 프로젝트 사전 및 선택한 V3 행과 대조한다. 이름 정의를 전문어로 넣었는지, 기능을 하위 장르로 만들었는지, 부모·공용·다른 장르가 암묵 혼입됐는지, 동명어·반동/탄퍼짐 같은 개념 경계가 맞는지 확인한다. 사전 예문·ref를 작품 규칙의 증거로 사용했는지와 신작 제안/확정 상태도 대조한다.

문제는 `본문 위치 | 사용 용어·node/key | 정의/별도 참조·작품 근거 | 수정 소유자 | 실제 수정·재확인`으로 기존 검수 기록에 남긴다. 용어 오용은 작성자에게, 작품 근거 부족은 research에 반환하고 수정된 원문을 재대조한다. HTML에는 확정 명칭과 독자에게 필요한 정의를 투영하고 원문과의 의미 일치를 확인한다. 조회 ID·해시·선택 이유·검수 이력은 내부 작업 기록이며 원작 독자용 보고서·HTML에 넣지 않는다.
