# 프로젝트 용어와 STE-KO 보고서 검수

원작 보고서와 신작 기획의 작성·수정·단독 호출에 기본 적용한다. 프로젝트 사전은 명칭과 개념 경계, [선택 V3](domain-dictionary.md)는 일반 개념, [STE-KO SPEC](ste-ko/SPEC.md)과 [표현 사전](ste-ko/dictionary.md)은 문장을 담당한다. 작품 근거와 사용자 확정 명칭을 먼저 보존한다. STE-KO는 이 보고서의 `문서` 표면으로 적용하며 전역 답변 스타일을 설치하거나 매 응답 유지 규칙을 켜지 않는다.

## 작성 전과 작성 중

1. 기존 프로젝트 사전·확정 용어 목록을 전체 읽는다. 실제 사용할 항목의 대표 명칭·명칭 상태·쉬운 정의·구별할 개념·작품 근거·본문 사용 위치를 정한다. 없으면 기존 기획 경로의 `00-glossary.md`에 필요한 항목만 만든다. 새 경쟁 사전을 만들지 않는다.
2. [V3 조회](domain-dictionary.md)로 메타데이터와 필요한 행만 읽는다. V3 예문을 작품 규칙으로 옮기지 않는다. 프로젝트 명칭과 일반 개념의 뜻이 다르면 프로젝트 사전에 작품별 정의와 근거를 밝힌다.
3. STE-KO 문서 표면의 표준 분량으로 쓴다. 대상·행동·결과를 분명히 하고 설명문은 25어절, 문단은 6문장을 기준으로 확인한다. 절차문·안전문은 SPEC의 별도 상한도 확인한다. 조사를 빼거나 모든 문장을 같은 길이로 자르지 않는다.
4. 공식 고유명·사용자 확정 명칭·실제 UI/인용/코드/오류 문자열·출처·수치/단위·부정/한정·미확인을 압축 때문에 지우거나 번역하지 않는다. 표현 대체가 개념이나 사실을 바꾸면 원문을 보존하고 검수 기록에 충돌·적용 제외 위치와 이유를 남긴다. 예외를 숨기거나 검사를 끄고 무위반으로 만들지 않는다.

## 작성 후 기본 실행

스킬의 실제 설치 경로를 기준으로 아래 실행기의 경로를 해석한다. 경로 인수는 실제 프로젝트 파일로 바꾸며 공용 스킬에 프로젝트 절대 경로를 저장하지 않는다.

```sh
# 작성 중: 자동 탐지만 한다. 이 성공은 최종 검수 완료가 아니다.
python3 scripts/check_report_language.py PROJECT/01-research.md --glossary PROJECT/00-glossary.md --lint-only
# 원문 수정 + 의미/수동 문체 검수 + 기존 기록 갱신 후: 최종 기본 관문
python3 scripts/check_report_language.py PROJECT/01-research.md --glossary PROJECT/00-glossary.md --workflow PROJECT/workflow.json
```

사용자가 지정한 V3를 사용했다면 두 명령 모두 `--domain-dictionary 실제V3경로`를 추가한다. 생략하면 스킬의 기본 V3를 입력으로 기록한다. 선택 node/key·조회 범위는 기존 V3 선택 기록과 의미 대조 근거에 남긴다.

각 독자용 산출물에 실행한다. 하위 작성자는 자동 탐지와 검수 결과를 총괄에게 넘기고 총괄만 workflow를 갱신한다. 단독 호출은 해당 실행자가 총괄을 맡는다. 자동 검사에서 발견한 위반은 실제 원문을 수정한 뒤 재실행한다. 고정 문자열의 오탐·정확성을 위한 규칙 충돌을 해소할 수 없으면 해당 발견과 이유를 기록하고 제한 상태로 인계한다. 자동 검사 0건으로 위장하지 않는다.

검수자는 제목·본문·표·캡션·링크 이름·부록의 실제 문장을 다음과 같이 대조한다.

- **용어 의미:** 같은 대상을 같은 명칭으로 부르는지, 프로젝트 사전의 정의·구별 및 선택 V3 행과 실제 문장이 맞는지 확인한다. 명칭 상태·작품 근거도 대조한다. 획득/해금 같은 사건을 구별하고 고유명과 고정 문자열을 보존한다. 별칭 문자열 검색은 후보 탐지일 뿐 의미 준수 판정이 아니다.
- **수동 문체:** SPEC의 적용 규칙을 읽고 의미·주체·명사 나열·절 연결·종결어미·사실/추론/미확인·수치·부정 보존을 실제 문장과 대조한다. 자동 검사 제외 영역도 읽는다. 대화/UI/코딩 전용 규칙은 보고서에 강제하지 않는다. 기본 규칙의 예외는 이유를 기록하고 필수 규칙 위반은 미해결로 남긴다.
- **수정 닫기:** `본문 위치 | 사용 용어/규칙 | 정의·근거/문제 | 수정 소유자 | 실제 수정·재확인 또는 제외 이유`를 기존 `05-validation.md`에 남긴다. 실제로 읽지 못한 범위는 미실행으로 기록하고 완료로 판정하지 않는다. 수정이 작품 의미를 바꾸지 않았는지 재독하고 최종 파일로 자동 검사를 다시 실행한다.

## 기존 상태 기록

새 로그 대신 기존 `workflow.json`의 `stages.validation.language_reviews`를 사용한다. 키는 workflow가 있는 프로젝트 경로 기준 보고서 상대 경로다. 각 보고서에 다음 항목을 둔다.

| 필드 | 기록할 값 |
| --- | --- |
| `input_sha256` | 최종 자동 실행 결과의 같은 필드 전체. 보고서·프로젝트 사전·실제 사용 V3·공용 지침·SPEC·표현 사전·lint·실행기와 공용 해시/앵커 함수의 실제 해시 |
| `terminology` | `status: pass/fail/not_run`, 실제 대조한 `locations` 문자열 배열, 정의·작품 근거와 대조 결과를 설명하는 `basis` 문자열 |
| `manual_style` | 같은 세 필드로 SPEC 문서 표면의 수동 검수 범위·판정·제외/미실행 이유 |
| `record` | 기존 `05-validation.md#고유앵커`의 대조 기록. `<a id="고유앵커"></a>`로 명시 |
| `record_sha256` | 저장 완료한 `05-validation.md` 전체의 실제 SHA-256 |

`locations`와 `basis`의 실제 문구를 해당 앵커 아래 기록한다. 여러 보고서를 검수하면 05-validation을 모두 저장한 뒤 각 항목의 record 해시를 갱신한다. 최종 실행기 출력의 종료 코드·탐지 범위·미실행·남은 충돌은 기존 validation notes와 검수 기록에 남긴다. 최종 명령이 0이고 실제 의미·수동 검수도 완료된 경우에만 해당 언어 검수 완료로 기록한다. `recorded_review_current`는 선언한 검수 기록과 현재 바이트가 일치한다는 뜻이며 기계가 의미나 검수의 진실성을 증명한다는 뜻이 아니다.

05-validation을 갱신하면 그 파일을 참조하는 기존 coverage 검수 기록의 해시도 현재 기록과 대조한다. 동일한 검수 내용을 유지한 기록 변경과 새 근거로 재검토할 변경을 구별하고 오래된 coverage 결과를 승계하지 않는다.

종료 코드 1은 문체 위반 또는 누락/오래된 검수 기록, 2는 입력·도구 오류다. 실패·미실행을 pass/done으로 올리지 않는다. 입력이 바뀌면 관련 언어 검수는 stale이며 재대조·실행 후 해시를 갱신한다. workflow 자체는 입력 해시에서 제외한다. 기존 단계 상태·coverage 검수·내용 충족·HTML 표시는 각각 유지한다. 전수 보고서는 기존 coverage 검사도 별도로 실행한다. 독자용 본문에는 검수 이력·해시를 섞지 않는다.

## 자동 검사의 실제 범위와 배포

STE-KO 원본은 [출처·채택 커밋·파일 SHA-256](ste-ko/UPSTREAM.json)에 고정했다. 원저장소는 https://github.com/beamonic/ste-ko 이며 MIT [LICENSE](ste-ko/LICENSE)를 함께 배포한다. SPEC/README는 0.5.0, 해당 커밋의 plugin manifest는 0.5.1이므로 채택 기준은 커밋이다. SPEC·dictionary·README·LICENSE·lint 원본은 수정하지 않았다. 원본 답변 스킬은 설치하지 않았다. SPEC/README의 상위 저장소용 링크는 원저장소 기준으로 읽는다.

원본 lint의 문서 표면 검사는 1.3·3.2·4.1·4.7·4.8·8.1·8.5의 일부 패턴만 탐지한다. 코드 펜스·표·인용·frontmatter·인라인 코드는 전부 또는 일부 제외한다. 4.8은 종결어미가 아니라 마지막 어절 전체의 반복이며, 한 줄의 어휘 위반은 첫 항목만 보고한다. UI 세부 상한과 의미·사실 보존은 검사하지 않는다. `대화`의 10.4는 이번 표면에서 실행하지 않는다. 자동 무위반을 SPEC 전체 준수·독자 이해도·재질문율 개선으로 보고하지 않는다.

원본 CLI는 누락 파일에도 0을 반환하고 사전 누락을 빈 목록으로 처리할 수 있다. 통합 실행기는 파일·공백 입력·사전 항목 로딩을 검증하고 원본 `check`를 호출해 이 성공 오인을 막는다. 다른 세션의 clone이나 샘플 경로가 필요 없도록 이 스킬 폴더 전체를 함께 배포한다.
