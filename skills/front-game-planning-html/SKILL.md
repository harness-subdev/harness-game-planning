# 게임 기획 HTML 열람본

프로젝트의 기획 문서를 읽기 좋은 정적 문서 허브로 만든다. 개별 호출도 가능하며 선행 스킬 전체 실행을 강제하지 않는다. 원본 문서가 일부만 있으면 누락을 명시하고 존재하는 내용으로 초안 열람본을 만든다.

## 입력과 원본

[공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)을 먼저 확인한다. 대상 프로젝트의 `game-planning/`을 기본으로 사용하되 사용자가 지정한 경로를 우선한다.

- `00-brief.md`, `01-research.md`, `02-concept.md`, `03-systems.md`, `04-progression.md`, `05-validation.md`가 기획 내용의 원본이다.
- `sources.json`의 출처와 `workflow.json`의 단계 상태를 함께 읽는다. 문서 주장과 출처의 연결, 미검증 수치, 미실행 테스트를 유지한다.
- `portal.json`은 원본에서 만든 파생 데이터이고 `index.html`은 빌드 결과다. 내용 수정은 원본에 반영한 뒤 둘을 재생성한다. 기존 파생 파일의 수동 편집으로 원본과 다른 결론을 만들지 않는다.

## 구성과 생성

1. [입력 형식](references/portal-format.md)을 읽고 원본의 핵심 판단, 규칙, 진행 구조, 검증 상태를 `portal.json`에 투영한다. 중요 제약과 미해결 질문을 요약에서 누락하지 않는다. 섹션과 항목의 ID는 후속 생성에서도 유지한다.
2. 문서에 맞는 섹션·상세 항목·표를 사용한다. 적 종류, 스테이지 수, 챕터 수, 전투 유무를 가정하지 않는다. 사실·자료 근거·가설·미검증을 구분하고 출처에는 `sources.json`의 식별자를 함께 넣는다.
3. 다음 명령을 이 스킬 경로를 기준으로 실행한다. 대상 경로에 공백이 있으면 따옴표로 감싼다.

   ```sh
   python3 scripts/build_portal.py /absolute/project/game-planning/portal.json /absolute/project/game-planning/index.html
   python3 scripts/self_check.py
   ```

4. HTML을 원본과 대조한다. 섹션·상세 항목·표 행의 누락, 미실행 테스트가 완료로 보이는 표현, 잘못된 근거 연결을 확인한다. 연결된 Chrome이 있으면 로컬 페이지에서 목차·상세 펼침·검색·좁은 화면을 확인한다. Chrome 기능이 없으면 그 범위만 미검증으로 기록한다. 브라우저 확인을 위해 Playwright로 전환하지 않는다.
5. 공통 계약에 따라 입력 해시, `portal.json`과 `index.html` 출력, 검수 결과를 총괄에 인계한다. `workflow.json`은 총괄만 기록한다. 개별 호출에서는 실행 에이전트가 총괄 역할을 명시적으로 맡아 인계 요약을 토대로 해당 HTML 단계만 갱신한다. 원본 변경으로 오래된 열람본은 `stale`이며 재생성 후에만 해소한다. `workflow.json` 자체는 입력 해시에서 제외하고 원문·출처·검증 문서의 해시를 전달한다. 표시한 선행 상태는 `input_states`로 인계하되 자신의 html running/done은 포함하지 않는다.

반복되는 JSON→HTML 변환은 제공된 표준 라이브러리 생성기를 재사용한다. 외부 폰트·CDN·이미지·API 요청 없이 `file://`와 로컬 HTTP에서 읽힌다. 입력의 HTML/Markdown은 실행하거나 해석하지 않고 문자 그대로 표시한다.

## 선택적 확장과 완료

게임 고유 도식이나 플레이어는 기획 판단에 필요한 경우에만 별도 산출물로 만든다. 범용 생성기에 게임 규칙이나 시뮬레이터를 넣지 않는다. 생략한 도식·플레이어는 `skipped`에 사유를 기록한다. 필요 여부가 불명확하면 현재 문서만으로 충분한지 판단해 생략할 수 있다.

열람본 준비 완료는 문서 내용과 표시를 검수했다는 뜻이다. `done` 또는 문서 준비 완료가 재미·밸런스·사업성의 실측 검증을 의미하지 않는다. 실제 테스트가 없으면 미실행 상태와 향후 검증 계획을 그대로 보여 준다.

최종 보고에는 HTML 절대 경로, 포함 문서, 반영한 결정 ID, 초안·미검증·가정·충돌·누락 사항, 실행한 검증과 다음 입력을 적는다. 일상적인 생성·갱신에 별도 승인 단계를 추가하지 않는다. 배포·공유·설치는 명시적으로 요청된 범위에서만 진행한다.
