# 플레이테스트 운영 양식

명시적으로 요청한 사람 플레이 시험을 준비하거나 실제 사람 플레이 자료를 분석할 때 사용한다. 신작 기획에서는 필요한 필드를 `05-validation.md`의 해당 `V-*`에 넣고 기획 규칙 `SYS/P-*` 정본과 원자료를 연결한다. 원작을 실제로 시험하는 요청에서는 조사 질문·보고서 절·확인할 게임 조건에 연결해 별도 작업 기록에 보관한다. 문서 검수·공개 플레이 영상 조사에는 참여자 운영 양식을 자동 적용하지 않는다. 미정은 미정, 미측정은 미측정으로 적으며 임의 값이나 가상의 사람 반응으로 빈칸을 채우지 않는다.

## 실행 전

| 필드 | 기록할 내용 |
| --- | --- |
| 질문과 범위 | 신작의 `V/C/SYS/P-*` 또는 요청한 원작 조사 질문·보고서 절, 검증할 규칙·경험, 이번 방법으로 판정할 수 있는 주장과 남는 질문 |
| 방법과 주체 | 검증 방법, 실제 플레이 주체 `human`/`agent`(해당할 때), 자료를 제공한 사람과 분석자를 구분 |
| 참여자 | 대상 플레이어와 선정 근거, 관련 경험·편의 조건, 모집·포함/제외 조건. 인원·세션 시간·판정 기준은 질문과 불확실성에 맞춘 이유를 함께 기록하고 고정 기본값을 쓰지 않음 |
| 플레이 준비 | 필요한 최소 행동·입력·피드백·콘텐츠와 준비 확인 조건, 빌드/문서/모델 버전, 실제 기기·입력 방식·환경·진행 구간·초기 상태. 준비되지 않은 항목은 인계 대상과 함께 `not_run` |
| 중립적 과제 | 참여자에게 보여 줄 과제 문구 그대로. 목표 경험의 정답·조작법·평가 의도를 암시하지 않으며, 질문에 필요한 안내가 있다면 제공 시점과 내용을 명시 |
| 시작 안내 | 진행자가 읽을 안내: 사람을 평가하는 테스트가 아님, 막힘·중단을 말할 수 있음, 필요한 경우 생각을 말하도록 요청. 녹화·자료 이용이 있다면 동의와 기록 범위 |
| 개입과 중단 | 도움을 줄 조건·순서·문구와 도움 제공 기록 방식, 기술 장애·불편·참여자 요청 등 중단 조건, 재시도 또는 종료 처리 |
| 측정과 기록 | 지표의 단위·시작/끝·성공/실패 정의·분모, 도움 받은 시행·중단·재시도·미측정의 처리, 기록 도구와 원자료 위치 |
| 판정과 수정 | 가능하면 사전 판정 기준과 이유, 적용 대상·조건·불확실성, 결과별 후속 행동과 소유 단계·항목 ID |

여러 검증 항목이 한 세션을 공유하면 공통 실행 조건은 한 번 적고 각 항목에서 참조한다. 문서 검토·수치 모델에는 사람 참여자 운영 칸을 강제하지 않는다.

## 실행 중과 실행 후

원자료에는 실제 일어난 내용만 적는다. 아래 구분을 유지하며 시각 또는 시행 번호로 연결한다.

| 기록 | 내용 |
| --- | --- |
| 행동 | 참여자·시행, 조건, 입력과 상태 변화, 도움·중단·장애, 측정값과 원자료 위치 |
| 발언 | 실제 발언과 시점. 정확한 인용인지 요약인지 표시 |
| 해석 | 어떤 행동·발언을 근거로 해석했는지, 다른 설명과 남는 불확실성 |

각 검증 항목에 계획과 실제 조건의 차이, 기준 충족 여부, 판정 가능한 주장 범위, 미실행·미측정 항목, 후속 수정 소유 단계와 위치를 남긴다. `observed`는 통과가 아니며 에이전트 플레이 관찰을 사람의 재미 증거로 바꾸지 않는다. 사람 자료도 해당 대상·조건·원자료가 뒷받침하는 범위를 넘어서 판정하지 않는다.

운영 질문은 [BMAD 플레이테스트 계획](https://github.com/bmad-code-org/bmad-module-game-dev-studio/blob/ff8870955203e1665f4bf75a64049078e6d4080c/src/workflows/gametest/gds-playtest-plan/SKILL.md)의 고정 커밋을 참고해 현재 V 계약에 맞게 재구성했다. BMAD의 인원·시간 기본값을 채택하지 않으며 이 양식 자체는 재미·검증 효과를 보증하지 않는다.
