# 게임 진행과 콘텐츠 구성

플레이어가 규칙을 배우고 활용하며 다시 시도할 수 있는 진행을 만든다. 스테이지 수, 적 수, 고정 난도 공식은 프로젝트에서 요청한 경우에만 사용한다.

## 시작과 소유권

- 먼저 [공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)을 읽는다.
- `00-brief.md`, `02-concept.md`, `03-systems.md`, 관련 조사와 기존 콘텐츠 데이터를 읽는다.
- 출력은 프로젝트 기획 경로의 `04-progression.md`다. 다른 단계 문서와 `workflow.json`은 수정하지 않는다.
- 선행 규칙이 미정이면 영향을 받는 진행을 가정으로 표시하고 독립적으로 설계 가능한 부분을 계속한다.
- 선형 스테이지, 비선형 탐색, 반복 세션, 시즌 중 실제 게임에 맞는 진행 단위를 선택한다.
- 요청 범위와 기존 콘텐츠 소유권을 보존한다. 모든 게임에 레벨·챕터·영구 성장을 추가하지 않는다.

## 진행 구조

1. 플레이어가 새로 알아야 할 것, 활용해야 할 것, 숙련해야 할 것과 회복할 기회를 찾는다.
2. 이 흐름이 적절한 구간에만 적용되도록 한다. 네 단계를 모든 콘텐츠마다 기계적으로 반복하지 않는다.
3. 각 진행 단위에 안정적인 `P-*` ID, 목적, 진입 조건, 관련 `SYS-*`, 완료·전환 조건을 둔다.
4. 선행 지식과 허용 경로를 연결한다. 비선형 진행은 다른 순서로 도달해도 이해 가능한지 검토한다.
5. 재시도·중단·복귀 시 유지되는 정보와 성장, 되돌릴 수 있는 선택을 명시한다.

## 난도와 배치

- 난도를 바꾸는 구체적인 요구를 설명한다: 읽기 부담, 판단 시간, 실행 정밀도, 자원 압박 등 게임에 맞는 축을 쓴다.
- 난도 점수 하나로 모든 부담을 숨기지 않는다. 계산 모델이 필요하면 공식·입력·단위·버전과 한계를 남긴다.
- 도입 직후 무엇을 확인하고, 어떤 조건에서 조합·변형·숙련 요구를 높이는지 설명한다.
- 새 규칙의 도입과 여러 제약의 동시 증폭이 과부하를 만들 수 있는 지점을 표시한다.
- 회복 구간은 단순히 쉬운 단계로 치환하지 않는다. 재학습·자원 회복·선택 재정렬 등 의도를 적는다.
- 조합과 금지 조건은 시스템 명세를 참조한다. 진행 문서에서 별도의 상충 규칙을 만들지 않는다.
- 성장 보상·경제가 있으면 획득·소모·해금 조건과 실패 후 손실을 연결한다.
- 세션·시즌 구조는 초기화 범위, 반복 변주, 복귀자의 진입 조건을 다룬다. 존재하지 않는 운영 요소는 생략한다.

## 대표 구간과 전체 범위

- 먼저 도입, 활용, 압박 또는 회복을 드러내는 대표 구간으로 구조를 확인한다. 고정 표본 수를 강제하지 않는다.
- 사용자가 전체 콘텐츠 범위를 요청했다면 대표 구간 검토 후 그 범위까지 작성한다. 샘플만 내고 완료하지 않는다.
- 전체 범위가 정해지지 않았으면 설계에 필요한 대표 구간과 확장 규칙까지만 작성하고 범위를 가정으로 표시한다.
- 자동 생성이나 표 복제는 의미 있는 차이와 규칙을 설명할 수 있을 때만 사용한다.
- 요청하지 않은 300개 스테이지, 10단계 반복 같은 수량·공식을 기본값으로 두지 않는다.
- 항목 수를 채우기 위한 중복을 피하고, 반복이 의도라면 플레이 경험의 차이나 반복 목적을 밝힌다.
- 초기 예상 시간·성공률·소모량은 목표 또는 계산값이다. 실제 플레이 결과와 분리한다.

## 산출물과 검수

- `04-progression.md`에 진행 구조, 도입·연결 조건, 난도·회복 의도, 요청 범위의 콘텐츠를 담는다.
- 각 주요 항목에 목적, 관련 시스템, 배치·구성, 성공·실패·전환, 근거와 검증 질문을 게임에 맞게 기록한다.
- 모든 필수 규칙이 요구되기 전에 전달되거나 발견 가능한지 확인한다.
- 도달 불가능한 진행, 해금 순환, 모순되는 자원 조건, 실제로 금지된 조합이 없는지 확인한다.
- ID 참조와 콘텐츠 범위를 확인하고 계산 난도와 관측 성공률이 섞이지 않았는지 확인한다.
- 산출물 경로 / 반영한 결정 ID / 남은 가정·충돌 / 검수 결과 / 다음 단계 입력을 반환한다.
- 문서 검수 결과와 실제 플레이 난도 검증을 구분한다. 후자는 검증 단계의 실행 근거가 필요하다.
