# 게임 진행과 콘텐츠 구성

원작의 확인된 플레이·콘텐츠 진행을 설명하거나 신작의 학습·성장·난도·회복·진행을 설계한다. 실제 게임에 맞는 진행 단위를 사용한다.

## 공통 진입과 출력 범위

- [문서 모드와 산출물 계약](../game-planning-workflow/references/artifact-contract.md#문서-모드와-원작-레퍼런스-보고서)에서 원작 분석과 신작 기획의 입력·출력·소유권을 확인한다. 제공된 사용자 피드백 정본과 용어·수정 목록은 전체 읽고 최신 확정 기준을 적용한다.
- [용어 정본과 명칭 대조](../game-planning-workflow/references/game-terminology.md#용어-정본과-명칭-대조) 및 [독자용 문체와 작업 기록의 경계](../game-planning-workflow/references/game-terminology.md#독자용-문체와-작업-기록의-경계)를 적용한다. 원작의 분석 결과는 지정 보고서에 연결하고 내용 질문·수정·제외 사유는 별도 작업 기록에 남긴다.
- 실제 화면·모션·UI가 설명에 필요하면 [조사의 실제 플레이 장면과 UI 취득](../game-planning-research/SKILL.md#실제-플레이-장면과-ui-취득)으로 질문과 필요한 화면을 전달한다. 캡처 취득 절차와 원자료 기록은 조사 단계에서 관리한다.
- 기존 정본·사용자 결정·다른 작성자의 소유권을 보존한다. 아래 신작 기획의 단계 파일과 명세 ID는 신작 기획을 작성할 때 사용한다.

## 원작 분석

1. 분석 범위의 본편·확장과 전체 구조 소개·상세 대상의 범위를 읽고 실제 플레이 흐름, 스테이지 종류·목표, 확인된 진입·선택·해금 관계를 정리한다.
2. [원작 보고서 계약](../game-planning-workflow/references/artifact-contract.md#원작-보고서의-정형-목차)에 따라 전체 흐름과 종류·진행 관계를 상세 사례보다 먼저 그림과 설명으로 제시한다. 사례 순서나 분석 편의상 묶은 분류를 실제 필수 진행 순서로 만들지 않는다.
3. 장기 목표·해금·진행 기록은 아웃게임, 현장 목표·완료 조건·실패·재시작·재도전은 인게임에 연결한다. 개별 콘텐츠 상세는 [해당 양식](../game-planning-workflow/references/artifact-contract.md#콘텐츠-상세-양식)을 적용한다.
4. 공략 변경과 같은 공략의 조작 조정, 관찰된 반복과 추정한 학습 효과를 구별한다. 없는 성장·회복 시스템이나 학습상 권장 순서를 만들지 않는다.
5. 진행 조건·필요한 장면이 부족하면 조사 질문·관련 절·필요한 화면을 [game-planning-research](../game-planning-research/SKILL.md)에 전달한다. 단독 호출은 요청한 분석을 지정 경로에 작성하고, 전체 보고서 참여는 해당 절·그림·근거·미확인을 정본 작성자와 [game-planning-validation](../game-planning-validation/SKILL.md)에 전달한다.

## 신작 기획

### 시작과 소유권

- 공통 진입에서 확인한 프로젝트 사전의 대표 명칭을 컨셉·규칙·진행 설명에 사용한다.
- `00-brief.md`, `02-concept.md`, `03-systems.md`, 관련 조사와 기존 콘텐츠 데이터를 읽는다.
- 출력은 프로젝트 기획 경로의 `04-progression.md`다. 다른 단계 문서와 `workflow.json`은 수정하지 않는다.
- 선행 규칙이 미정이면 영향을 받는 진행을 가정으로 표시한다. 추가 근거가 필요한 질문은 조사 단계에, 진행과 규칙의 내용 충돌은 검수 단계에 전달한다.
- 선형 스테이지, 비선형 탐색, 반복 세션, 시즌 중 실제 게임에 맞는 진행 단위를 선택한다.
- 요청 범위와 기존 콘텐츠 소유권을 보존한다. 모든 게임에 레벨·챕터·영구 성장을 추가하지 않는다.
- 자원 흐름·내러티브 분기·비선형 도달 순서 등이 진행의 위험이면 [선택형 질문](../game-planning-workflow/references/genre-questions.md)에서 필요한 부분만 읽는다. 기존 문서가 답한 질문은 참조하고 반복해서 묻지 않는다.

### 진행 구조

1. 플레이어가 새로 알아야 할 것, 활용해야 할 것, 숙련해야 할 것과 회복할 기회를 찾는다.
2. 이 흐름이 적절한 구간에만 적용되도록 한다. 네 단계를 모든 콘텐츠마다 기계적으로 반복하지 않는다.
3. 각 진행 단위에 안정적인 `P-*` ID, 목적, 진입 조건, 관련 `SYS-*`, 완료·전환 조건을 둔다.
4. 선행 지식과 허용 경로를 연결한다. 비선형 진행은 다른 순서로 도달해도 이해 가능한지 검토한다.
5. 재시도·중단·복귀 시 유지되는 정보와 성장, 되돌릴 수 있는 선택을 명시한다.

### 난도와 배치

- 난도를 바꾸는 구체적인 요구를 설명한다: 읽기 부담, 판단 시간, 실행 정밀도, 자원 압박 등 게임에 맞는 축을 쓴다.
- 난도 점수 하나로 모든 부담을 숨기지 않는다. 계산 모델이 필요하면 공식·입력·단위·버전과 한계를 남긴다.
- 도입 직후 무엇을 확인하고, 어떤 조건에서 조합·변형·숙련 요구를 높이는지 설명한다.
- 새 규칙의 도입과 여러 제약의 동시 증폭이 과부하를 만들 수 있는 지점을 표시한다.
- 회복 구간은 단순히 쉬운 단계로 치환하지 않는다. 재학습·자원 회복·선택 재정렬 등 의도를 적는다.
- 조합과 금지 조건은 시스템 명세를 참조한다. 진행 문서에서 별도의 상충 규칙을 만들지 않는다.
- 성장 보상·경제가 있으면 획득·소모·해금 조건과 실패 후 손실을 연결한다.
- 세션·시즌 구조는 초기화 범위, 반복 변주, 복귀자의 진입 조건을 다룬다. 존재하지 않는 운영 요소는 생략한다.

### 대표 구간과 전체 범위

- 먼저 도입, 활용, 압박 또는 회복을 드러내는 대표 구간으로 구조를 확인한다. 고정 표본 수를 강제하지 않는다.
- 사용자가 전체 콘텐츠 범위를 요청했다면 대표 구간 검토 후 그 범위까지 작성한다. 샘플만 내고 완료하지 않는다.
- 전체 범위가 정해지지 않았으면 설계에 필요한 대표 구간과 확장 규칙까지만 작성하고 범위를 가정으로 표시한다.
- 자동 생성이나 표 복제는 의미 있는 차이와 규칙을 설명할 수 있을 때만 사용한다.
- 요청하지 않은 300개 스테이지, 10단계 반복 같은 수량·공식을 기본값으로 두지 않는다.
- 항목 수를 채우기 위한 중복을 피하고, 반복이 의도라면 플레이 경험의 차이나 반복 목적을 밝힌다.
- 초기 예상 시간·성공률·소모량은 목표 또는 계산값이다. 실제 플레이 결과와 분리한다.

### 산출물과 검수

- `04-progression.md`에 진행 구조, 도입·연결 조건, 난도·회복 의도, 요청 범위의 콘텐츠를 담는다.
- 각 주요 항목에 목적, 관련 시스템, 배치·구성, 성공·실패·전환, 근거와 검증 질문을 게임에 맞게 기록한다.
- 모든 필수 규칙이 요구되기 전에 전달되거나 발견 가능한지 확인한다.
- 도달 불가능한 진행, 해금 순환, 모순되는 자원 조건, 실제로 금지된 조합이 없는지 확인한다.
- ID 참조와 콘텐츠 범위를 확인하고 계산 난도와 관측 성공률이 섞이지 않았는지 확인한다.
- 구현 요청이 있으면 관련 `P-*`, 규칙 정본 `SYS-*`와 `V-*`를 [공통 계약의 구현 요청 시 인계](../game-planning-workflow/references/artifact-contract.md#구현-요청-시-인계)에 연결한다. 진행 문서에서 구현 수락 조건용 경쟁 규칙을 만들지 않는다.
- 산출물 경로 / 반영한 결정 ID / 남은 가정·충돌 / 검수 결과 / 다음 단계 입력을 반환한다.
- 문서 검수 결과와 실제 플레이 난도 검증을 구분한다. 후자는 검증 단계의 실행 근거가 필요하다.
