# 게임 기획 자료 조사

기본 대상은 개발 예정·개발 중인 게임의 기획이다. 자료 목록보다 이후 기획 결정을 뒷받침하는 근거를 만든다. 특정 게임의 콘텐츠 수나 성공 공식을 다른 게임의 기본값으로 가져오지 않는다.

## 시작과 소유권

- 먼저 [공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)을 읽는다.
- 사용자 요청, 기존 기획 문서, 실제 구현·데이터, 이미 확인된 결정과 조사 결과를 읽는다.
- 기존 프로젝트의 기획 경로를 사용하고, 없으면 `game-planning/`를 사용한다.
- `00-brief.md`, `sources.json`, `01-research.md`를 작성·보완한다. 기존 브리프의 확정 결정을 덮어쓰지 않는다.
- 총괄이 관리 중인 브리프 변경은 변경 제안으로 인계한다. `workflow.json`과 다른 단계 문서는 수정하지 않는다.
- 단독 호출에서도 필요한 조사부터 수행한다. 실행 결과를 바꾸는 누락 정보만 질문하고 독립적인 조사는 계속한다.

## 조사 범위 정하기

1. 브리프에 대상 경험·플레이어·플랫폼·입력·장르·개발 제약·요청 범위를 정리한다.
2. 분위기·손맛·플레이어 판타지를 포함한 사용자 원문 요구를 브리프에 보존하고, 확인된 결정·미정 질문·에이전트의 가정과 구분한다.
3. 이미 정한 범위를 재협상하지 않는다. 불명확한 항목이 작업을 막지 않으면 가정을 밝혀 초안을 진행한다.
4. 컨셉·규칙·진행 설계에 실제 영향을 주는 조사 질문을 정하고 각 질문의 필요한 증거를 고른다.
5. 비교 작품은 유사 장르라는 이유만으로 늘리지 말고 조작, 선택, 세션 구조 등 질문에 맞춰 선정한다.

## 근거 수집

- 현재성이 필요한 정보는 확인 시점에 조회한다. 공식 게임·개발사 자료, 매뉴얼, 패치 기록, 원저자 발표 등 1차 자료를 우선한다.
- 공식 설명도 설계 의도에 관한 주장일 수 있다. 실제 플레이 행동을 입증하는 자료와 구분한다.
- 페이지 검사·스크린샷·직접 상호작용은 연결된 Chrome의 지원 API를 사용한다. Playwright를 사용하지 않는다.
- 접근 가능한 검색·문서 도구로 출처를 찾고, 핵심 주장을 뒷받침하는 실제 원문을 확인한다.
- 직접 플레이, 영상 관찰, 문서 설명을 구분한다. 영상은 버전과 관찰 구간을, 직접 관찰은 플레이 주체(human/agent), 조건과 재현 절차를 남긴다.
- 레퍼런스에서 확인한 동작과 내부 규칙·수치의 추정을 구분한다. 레퍼런스 자체의 규칙 명세화는 그 작업이 요청됐을 때만 수행한다.
- 경쟁작 전체 기획서나 유료·비공개 자료를 복제하지 않는다. 필요한 범위의 관찰·요약과 근거 위치를 남긴다.
- 접근하지 못한 페이지나 수행하지 않은 플레이는 확인된 근거로 쓰지 않는다. 접근 제한과 대체 근거를 기록한다.
- 출처마다 안정적인 `S-*` ID, 제목, 실제 URL/파일 위치, 접근일, 알려진 게시일·버전, 종류와 신뢰도 한계를 기록한다.
- 상충하는 설명은 버전·플랫폼·관찰 조건 차이를 확인하고 양쪽 출처와 영향을 받는 결정을 보존한다.

## 조사 문서 작성

- `sources.json`은 공통 계약의 `schema_version`, `sources`, `findings`, `conflicts` 구조를 따른다.
- 각 `R-*` 항목의 관찰, 해석, 적용 후보를 별도 필드에 쓴다. 내부 규칙 추정은 해석에 남기고 확인된 동작으로 표현하지 않는다.
- 출처가 없는 아이디어는 새 가설로 표시한다. 여러 매체가 반복한 주장을 독립 증거 여러 개로 세지 않는다.
- `01-research.md`에는 조사 질문, 검색 범위, 질문별 비교·차이와 레퍼런스별 채택/제외/변경·보류 이유를 쓴다. 이유를 사용자 요구·제약과 관련 `S/R/D-*`에 연결한다.
- 브리프의 각 원문 요구를 `01-research.md`에서 반영 위치 또는 제외 `D-*`, 남은 충돌과 대조한다. 아직 없는 `C/SYS/P/V-*`는 예정 참조로 남기고, 새 제외 결정은 제안으로 구분한다.
- 채택 제안은 `D-*` ID와 근거 `S/R-*`를 연결하고, 사용자가 결정하지 않은 내용은 `proposed`로 둔다.
- 주요 결론에는 근거의 적용 범위와 남은 불확실성을 붙인다. 모르는 수치에는 0을 넣지 않는다.
- 자료 건수나 문서 분량 목표를 강제하지 않는다. 주요 질문의 판단 근거와 큰 반례가 확보되면 멈춘다.
- 해결되지 않은 질문은 추가 자료가 바꿀 결정과 함께 남겨 다음 조사 비용을 판단할 수 있게 한다.

## 검수와 인계

- 실제로 확인한 출처만 기록했는지, 링크·날짜·관찰 위치가 독자가 추적할 수 있는지 확인한다.
- 출처 ID 참조와 JSON 구조, 원문 요구 대조의 누락·미해결 충돌을 확인하고 사용자 요구·관찰·가설이 섞인 표현을 바로잡는다.
- 컨셉 단계가 판단할 핵심 경험, 기회, 제약, 미해결 충돌을 간결하게 정리한다.
- 산출물 경로 / 반영한 결정 ID / 남은 가정·충돌 / 검수 결과 / 다음 단계 입력을 반환한다.
- 조사 문서 완료를 시장성·재미 검증이나 사용자 승인으로 표현하지 않는다.
