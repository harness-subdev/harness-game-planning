# 게임 기획 자료 조사

조사 질문에 답할 자료를 확인하고, 게임의 구조·행동·결과를 근거와 함께 설명한다. 원작 보고서 작성과 신작 기획을 위한 자료 조사는 [공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)의 요청별 산출물로 구분한다.

## 기본 용어·문체 검수

[프로젝트 용어 + STE-KO 보고서 검수](../game-planning-workflow/references/report-language.md)를 단독 호출에도 적용한다. 작성 전 프로젝트 사전의 실제 사용 항목·명칭 상태·정의·구별을 확인하고 선택 V3와 STE-KO 문서 표면을 적용한다. 작성 후 자동 검사와 실제 문장의 의미·수동 문체 대조를 수행하고 원문 수정·재검사로 닫는다. 총괄은 기존 workflow/05-validation에 범위·해시·판정을 기록하고 최종 실행기를 호출한다. 하위 작업은 실제 실행 결과와 미실행을 총괄에게 인계한다. 단독 실행자는 총괄 역할을 맡는다. 자동 탐지만으로 의미 준수나 최종 완료를 주장하지 않는다.


## 시작과 소유권

- 공통 계약에서 문서 모드·출력 경로·정본 소유자를 확인한다. 제공된 사용자 피드백 정본과 용어·수정 목록은 요약 대신 전체 읽고 최신 확정 기준을 적용한다.
- 기존 사용자 요청, 조사 문서·출처·캡처, 확정 결정과 실제 구현·데이터 중 요청에 관련된 자료를 읽는다. 수정 예시는 새로 확인한 게임 사실로 사용하지 않는다.
- 기존 프로젝트의 기획·보고서 경로를 재사용한다. 없으면 `game-planning/`를 사용한다. 용어 사전은 공통 계약과 [게임 용어·문체 기준](../game-planning-workflow/references/game-terminology.md)에 따라 본문보다 먼저 확인·보완한다.
- 원작 분석은 지정된 보고서 또는 `01-research.md`와 기존 `sources.json`·증거 기록을 작성한다. 분석 대상·범위·조건을 기록하되 신작의 장르·예산·팀·목표 경험을 정하기 위한 브리프를 만들지 않는다.
- 신작 기획은 `00-brief.md`, `sources.json`, `01-research.md`를 작성·보완한다. 사용자 원문 요구와 확정 결정은 보존하고, 에이전트의 가정·새 제안과 구별한다. 총괄이 관리하는 브리프 변경은 제안으로 인계한다.
- `workflow.json`과 다른 단계 정본은 총괄·해당 소유자가 수정한다. 단독 호출도 요청한 조사와 문서까지 작성하며, 자료로 답할 수 없는 질문은 미확인 범위를 밝혀 전달한다.

## 조사 질문과 범위

1. 요청한 대상·본편/확장·버전·플랫폼·상세 분석 범위를 정리한다. [V3 도메인 사전 조회와 보고서 적용](../game-planning-workflow/references/domain-dictionary.md)으로 메타데이터를 먼저 확인해 장르·하위 유형 노드와 대응하고, 이름 정의와 전문어를 나누어 필요한 행만 읽는다. 선택 이유·주 범위/별도 참조·node ID/key·사전 경로/해시를 기존 작업 기록에 남긴다. 프로젝트 피드백/확정 용어 목록 전체 읽기를 V3 본문 전체 읽기로 확대하지 않는다. 원작 보고서는 공통 계약의 정형 목차와 콘텐츠 상세 양식에서 실제 해당하는 항목을 조사 질문으로 바꾼다.
2. 질문별로 설명할 규칙·행동·변화, 필요한 원문과 실제 화면, 관찰 조건을 대응시킨다. 전투·장비·미션이 없는 게임은 실제 대상·상호작용·목표를 조사한다.
3. 이미 확정한 범위를 재협상하지 않는다. 판단을 막지 않는 미정 항목은 가정을 밝히고 진행하며, 정확한 HP·스토리·히든 조건·프레임을 빈칸 채우기 위해 추정하지 않는다.
4. 신작 비교 작품은 조작·선택·반복·진행 등 질문에 맞춰 고른다. 유사 장르라는 이유만으로 자료 건수나 작품 수를 늘리지 않는다.

## 근거 수집

- 현재성이 필요한 정보는 실제 조사 시점에 조회한다. 공식 게임·개발사 자료, 매뉴얼, 패치 기록과 원저자 발표 등 1차 자료를 우선한다. 핵심 주장은 검색 결과가 가리키는 실제 원문까지 확인한다.
- 공식 자료의 설계 의도, 문서의 규칙 설명, 실제 플레이 행동을 구별한다. 가이드·위키·리뷰·개인 영상은 공식 자료로 표시하지 않는다.
- 페이지 검사·상호작용·스크린샷은 연결된 Chrome의 지원 API를 사용한다. 접근하지 못한 원문이나 수행하지 않은 관찰을 확인 완료로 기록하지 않는다.
- 출처마다 안정적인 `S-*` ID, 제목, 직접 URL/파일 위치, 실제 접근일, 알려진 게시일·버전, 자료 종류와 한계를 남긴다. 게시일을 모르면 `null`로 둔다.
- 상충하는 설명은 원문·버전·플랫폼·관찰 조건을 대조하고 양쪽 근거와 영향을 받는 주장·결정을 기존 출처 기록에 남긴다. 경쟁작의 유료·비공개 자료를 복제하지 않는다.

## 실제 플레이 장면과 UI 취득

실제 동작과 화면을 설명하는 조사에는 다음 순서를 적용한다. 이 절은 게임 기획 스킬군의 장면 취득 절차 정본이다. 직접 게임 실행을 일괄 전제하지 않으며, 공개 영상으로 확인 가능한 행동을 조사한다.

1. 기존 조사 기록에 `조사 질문/본문 위치 | 설명할 행동·변화 | 필요한 실제 화면/UI·전후 장면 | 확인할 관찰 조건`을 대응시킨다. 캐릭터·체력·카드·장비 선택·코인·상점·지도·진행/결과의 설명에는 각각을 보여 주는 실제 UI도 포함한다.
2. 웹서칭으로 설명 대상의 공개 실제 플레이 영상을 찾는다. 공식 게임·개발사 원자료를 우선하고 부족하면 원저자의 공개 플레이 영상을 사용하며 공식 자료와 구별한다. 제목·썸네일은 선정 단서이며 동작 확인 근거가 아니다.
3. 연결된 Chrome의 지원 접근성·입력·스크린샷 API로 정확한 원영상 탭(ID·URL)을 열고 필요한 구간을 연속 관찰한다. 페이지 제목·설명만 읽었거나 재생이 차단됐다면 화면 관찰로 세지 않는다. 네이티브 창 캡처 실패만으로 탭 접근 불가를 판단하지 않고 해당 탭의 접근성 상태·지원 입력·스크린샷을 확인한다. Playwright를 사용하지 않는다.
4. 게임·캐릭터·스테이지·본편/확장·버전·난이도·장비 등의 조건을 확인하고 알 수 없는 조건을 기록한다. 설명에 쓸 시점의 실제 장면을 캡처해 로컬 저장한다. seek 후 표시 시각과 재생/일시정지 상태·취득 기록을 **최종 저장 픽셀**과 대조하고 저장한 이미지도 열어 대상·행동·시점이 맞는지 확인한다. 전후 변화·모션에는 필요한 양쪽 장면을 취득하고 각각 대조한다.
5. 캡처를 확보한 장면은 본문의 같은 위치에 **영상 시각 + 정확히 그 시점의 캡처 + 보이는 행동/변화 설명 + 직접 원영상 링크**를 배치한다. 사진 바로 옆이나 아래에서 캐릭터·적·물체가 무엇을 하고 무엇이 달라지는지 설명하고, 해당 규칙·선택과 연결한다. 실제 UI도 관련 설명 가까이에 둔다. 화면에 없는 버튼 입력·의도·행동을 덧붙이지 않는다.
6. 특정 시각을 쓰는 문장·표 행·캡션을 원영상·관찰 기록·출처와 대조한다. **캡처가 없으면 항목을 삭제하지 않고 문서 수준의 설명으로 유지한다.** 영상으로 확인한 내용은 설명·확인한 시각·직접 원영상 링크와 함께 “영상 관찰, 캡처 미첨부”로 표시한다. 문서나 제공 자료만으로 확인한 내용은 “자료 설명”으로 출처를 밝히고, 장면을 확인하지 못한 부분은 “장면 미확인”으로 구별한다. 확인하지 못한 행동·시각은 관찰 사실로 쓰지 않으며, 원자료의 시각 메모를 남길 때도 재확인 여부를 밝힌다. 캡처의 픽셀·시각·대상이 불일치하면 그 이미지를 사용하지 않고 같은 기준으로 설명을 유지한다. 내부 저장만 된 파일·다른 시각 이미지를 첨부한 것으로 세지 않는다.
7. 기존 `sources.json`과 증거 기록에서 출처 제목/직접 URL·원저자·취득일·시각/구간·관찰 조건·권리/이용 표시·원본/최종 파일·SHA-256을 추적한다. 적합한 기존 캡처는 재사용하되 실제 취득일을 유지하고 이번 재대조와 구별한다. 파일·해시는 실제 취득한 이미지에만 기록하며 캡처가 없으면 미취득으로 남긴다. 필요한 최소 캡처만 남기며 영상 전체 다운로드·재업로드를 자동 의무로 만들지 않는다.
8. 본문 위치별 시각·캡처·설명·링크 대응과 문서로 유지한 항목의 근거 종류·캡처 유무·미확인을 작성자와 [game-planning-validation](../game-planning-validation/SKILL.md), [front-game-planning-html](../front-game-planning-html/SKILL.md)에 인계한다. 취득 실패·차단·미지원은 작업 기록이며 확인·추출 완료가 아니다. 이미지 개수로 설명에 필요한 근거의 충족을 판단하지 않는다.

외형 그림·스프라이트·생성 이미지·다른 스테이지 화면은 실제 움직임의 증거를 대신하지 못한다. 외형 설명에 필요한 정지 이미지는 역할을 밝히고 직접 출처·취득일·권리와 함께 사용한다. 정지 화면 하나에서 이동 속도·피해 판정·저장 성공을 확정하지 않는다.

## 관찰과 해석의 경계

기존 질문은 주장별로 `영상에서 확인한 사실 / 영상 기준 측정값 / 반복 관찰로 뒷받침된 규칙 추론 / 자료 설명 / 여전히 미확인`으로 구별한다. 한 사건을 확인했다고 복합 규칙 전체를 확정하지 않는다. 실제 직접 플레이는 플레이 주체(`human`/`agent`), 조건과 재현 절차를 기록하며 공개 영상 관찰과 구별한다.

- 영상에서 보이는 이동·사격·사망 등 행동과 사람의 입력·의도·감정·학습·재미를 구별한다. 반복 플레이만으로 실제 숙련 향상이나 사람 시험 완료를 주장하지 않는다.
- 수치를 쓰면 `측정 대상 | 원영상 구간/표본 | 초·화면 좌표와 기준점 | 계산 방법 | 편집·배속·프레임률·해상도 확인 상태 | 오차·적용 범위`를 기존 기록에 남긴다. 초 단위 표시만 확인되면 그 해상도에 맞는 근사값으로 쓴다.
- 영상 경과와 영상 프레임은 게임 실제 시간·내부 프레임·충돌 판정과 다르다. 내부 체력·히트박스·동시 사건 처리·저장·난수는 관찰만으로 확정하지 않는다. 미확인 값에 `0`이나 합격값을 넣지 않는다.
- 주요 결론에는 근거가 적용되는 조건과 남은 불확실성을 붙인다. 새 프로젝트의 설계 선택·계산·가설은 원작에서 확인한 사실과 별도로 표시한다.

## 조사 문서 작성

`sources.json`은 공통 계약의 `schema_version`, `sources`, `findings`, `conflicts` 구조를 따른다. `R-*`의 관찰과 해석은 구별하며, `application`은 신작의 실제 적용 후보가 있을 때만 추가한다. 출처 없는 아이디어는 새 가설로 표시하고, 여러 매체가 반복한 같은 주장을 독립 근거 여러 개로 세지 않는다.

| 요청 | 작성할 내용 |
| --- | --- |
| 원작 레퍼런스 보고서 | 공통 계약의 정형 목차·장르별 콘텐츠 상세 양식으로 지정 정본에 게임 개요·메커니즘·핵심 설계 특징·참고자료와 조사 범위를 작성한다. 제목·문체·독자용 본문과 작업 기록의 경계는 게임 용어·문체 기준을 따른다. 조사 질문·검색 범위·관리 ID·내부 검수는 기존 작업 기록에 남긴다. |
| 신작 기획 자료 조사 | `01-research.md`에 조사 질문·검색 범위·질문별 비교와 차이, 채택/제외/변경·보류 이유를 사용자 요구·제약과 `S/R/D-*`에 연결한다. 브리프 원문 요구의 반영/제외·남은 충돌을 대조하고 새 결정은 `proposed`로 둔다. 아직 없는 `C/SYS/P/V-*`는 예정 참조로 남긴다. |

자료 건수나 분량 목표를 강제하지 않는다. 주요 질문의 근거와 큰 반례가 확보되면 정리하고, 남은 질문에는 추가 자료로 달라질 주장·결정을 적는다.

## 내용 보완·검수·인계

집필에는 선택 용어의 정의·구별 기준·의미 차이·예문·ref를 확인해 명확한 명칭을 사용하고 본문 위치를 프로젝트 사전에 연결한다. 사전 정의 출처와 해당 작품의 실제 규칙 근거를 구별해 검수 단계로 인계한다. 자료와 초안은 [내부 내용 검토](../game-planning-workflow/references/deep-interview.md)에 따라 대조하고 실제 수정한다. 전체 실행에서는 총괄의 검토에 참여하며 단계마다 같은 검토를 다시 시작하지 않는다. 제목·용어·출처 참조·JSON 구조, 관찰과 해석의 구분, 장면 대응과 누락을 확인한 뒤 필요한 결과를 다음 담당에 전달한다.

| 필요한 보완 | 기존 담당 스킬과 입력 | 받아서 반영할 결과·다음 단계 |
| --- | --- | --- |
| 원작의 핵심 플레이·선택·시스템 연결 해석 | [game-planning-concept](../game-planning-concept/SKILL.md)에 확인된 구조·행동·선택 근거와 해당 질문 | 원작 해석과 한계를 보고서 작성자에게 반환 |
| 원작 규칙·상호작용 관계 정리 | [game-planning-systems](../game-planning-systems/SKILL.md)에 관찰·자료 설명·미확인 질문 | 확인 범위의 규칙 설명을 작성자에게 반환 |
| 원작 진행·해금·재도전 관계 정리 | [game-planning-progression](../game-planning-progression/SKILL.md)에 실제 진행 근거와 조건 | 확인된 관계·도식 입력을 작성자에게 반환 |

| 완성한 조사·보고서 검수 | game-planning-validation에 정본·사전·출처·장면 대응·남은 한계 | 수정 위치·근거를 소유자에게 반환하고 수정한 정본을 HTML 담당에게 전달 |
| 신작 컨셉 결정 | game-planning-concept에 브리프·비교 근거·채택 제안·가정/충돌 | 신작 컨셉과 후속 설계 입력 |

원작 지원 작업은 필요한 해석만 반환한다. 보고서 내용을 보완한다는 이유로 신작 MVP·제작 계약·QA·사람 시험을 만들지 않는다. 반환에는 산출물·사전 경로, 반영한 근거 또는 결정, 남은 충돌, 실제 확인한 범위, 다음 담당이 사용할 입력을 포함한다. 조사 문서 완료는 사용자 승인·시장성·재미 검증과 구별한다.
