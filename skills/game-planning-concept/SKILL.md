# 게임 컨셉 구체화

조사에서 얻은 근거를 개발 예정·개발 중인 게임의 플레이 경험과 검증 가능한 재미 가설로 바꾼다. 게임 화면·자산 제작과 런타임 구현, 실제 플레이테스트는 별도 범위다.

## 시작과 소유권

- 먼저 [공통 산출물 계약](../game-planning-workflow/references/artifact-contract.md)을 읽는다.
- `00-brief.md`, `sources.json`, `01-research.md`와 기존 컨셉, 사용자 결정, 구현 제약을 읽는다.
- 출력은 프로젝트 기획 경로의 `02-concept.md`다. 다른 단계 문서와 `workflow.json`은 수정하지 않는다.
- 선행 문서가 없으면 사용자 자료로 확인 가능한 최소 입력을 추출하고 누락 근거를 명시한다.
- 플레이어 경험이나 범위를 크게 바꾸는 미지수만 질문한다. 답과 무관하게 가능한 부분은 계속한다.
- 단독 호출에서도 이미 결정된 내용을 보존하고, 확정하지 않은 선택은 가정 또는 제안으로 남긴다.

## 핵심 경험 찾기

1. 누가 어떤 상황에서 어떤 행동을 반복하며 무엇을 느끼도록 할지 한 문장으로 표현한다.
2. 재미 가설에 안정적인 `C-*` ID를 부여한다. 플레이어 행동, 기대 반응, 성립 조건을 구체화한다.
3. 각 가설을 사용자 요구 또는 조사 `R-*`와 연결한다. 독자적인 발상은 새 가설임을 밝힌다.
4. 테마·분위기·손맛·판타지의 원문 요구를 보존하고, 어떤 행동·표현·피드백으로 느껴질지 가설화한다. 콘텐츠 양을 경험의 근거로 대신하지 않는다.
5. 판단을 바꿀 대안이 있을 때만 비교한다. 같은 결론의 표현만 다른 후보를 채우지 않는다.

## 디자인 판단 기준

- 실제 채택·거절을 이끄는 디자인 원칙을 정한다. 각 원칙에 판단 기준과 후보의 채택/거절 사례를 쓰고 관련 `D-*`에 연결한다. 원칙 개수는 고정하지 않는다.
- 각 `C-*`에 규칙 `SYS-*` → 예상 반복 행동/전략 → 기대 경험 → 성립하지 않을 반례·관찰 질문 `V-*`를 연결한다. 아직 없는 SYS/V는 예정 참조로 표시하고 예상 행동을 관측 사실로 쓰지 않는다.

## 플레이 루프 정의

- 핵심 반복을 플레이어가 인지할 수 있는 순서로 쓴다: 상황 인지 → 선택·입력 → 결과·피드백 → 다음 선택.
- 각 연결에서 무엇을 보고, 무엇을 바꾸며, 결과를 어떻게 이해하는지 명시한다.
- 중요한 선택은 선택지, 기회비용·위험, 즉시 결과와 다음 선택에 미치는 영향을 설명한다.
- 의미 있는 선택이 없는 구간은 그 의도와 관찰할 위험을 기록한다. 모든 장르에 복잡한 선택을 강제하지 않는다.
- 성공·실패·중단·재시작 조건과 다음 시도에 남는 것을 정의한다. 열린 플레이에는 적절한 완료·전환 조건을 쓴다.
- 세션 길이, 재시도 비용, 목표 달성 시간은 목표 또는 가정으로 표시하고 단위를 붙인다.
- 플랫폼과 입력 제약 아래에서 행동과 피드백이 실행 가능한지 확인한다.
- 외부 작품의 규칙을 그대로 묶지 말고, 채택 이유와 이 게임의 조건에 맞춘 변경을 설명한다.

## 최소 범위와 결정

- MVP는 핵심 가설을 확인하는 데 필요한 플레이 경험과 시스템으로 한정한다. 테스트할 경험에 필요한 최소 디자인·구현 범위와 조건을 후속 SYS/V 및 제작 작업으로 인계한다.
- 반드시 필요한 요소, 가설 확인 뒤 추가할 요소, 이번 범위에서 제외할 요소를 구분한다.
- 콘텐츠 개수나 개발 일정을 임의로 확정하지 않는다. 필요한 경우 산정 가정과 범위를 기록한다.
- 중요한 선택은 `D-*` ID, 근거, 상태와 영향받는 `C-*`를 가진다.
- 사용자 결정·기존 승인 자료만 `confirmed`로 취급한다. 문서 작성 완료가 승인 요청의 자동 관문은 아니다.
- 합의와 충돌하는 제안은 충돌을 명시하고 기존 결정을 보존한다. 상위 문서를 조용히 고치지 않는다.

## 산출물과 검수

- `02-concept.md`에 한 줄 컨셉, 대상 경험, 재미 가설, 핵심 반복, 주요 선택, 성공·실패·재시작을 담는다.
- 이어서 디자인 원칙과 판단 사례, MVP·제외 범위, 근거 연결, 결정과 미정 사항, 시스템 단계에 전달할 조건을 담는다.
- 문서 형식은 게임에 맞게 줄인다. 없는 시스템이나 메타 성장 요소를 채우지 않는다.
- 원칙이 실제 선택을 가르는지, 모든 핵심 가설이 규칙·반복 행동/전략·기대 경험·반례와 검증 질문으로 이어지는지 확인한다.
- 루프 안에서 승리·실패 조건, 제약, MVP 범위가 서로 모순되지 않는지 확인한다.
- 안정적인 ID와 실제 참조 대상이 일치하는지 확인하고 아직 없는 후속 ID는 예정 참조로 표시한다.
- 산출물 경로 / 반영한 결정 ID / 남은 가정·충돌 / 검수 결과 / 다음 단계 입력을 반환한다.
- 완료는 컨셉 문서가 검수됐다는 의미다. 재미가 입증되거나 게임이 구현됐다고 표현하지 않는다.
