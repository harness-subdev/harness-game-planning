게임 기획 워크플로우

문서 검수 완료

자료 조사부터 실제 게임 기획서까지. 총괄 1개와 단계별 6개 스킬로 만들고, 수정하고, HTML로 읽습니다.

문서 준비 상태와 게임 검증은 별개입니다. 문서 검수 완료는 재미·밸런스·사업성의 실측 검증을 의미하지 않습니다.

검색 결과가 없습니다. 다른 단어로 검색해 주세요.

전체 흐름

문서 검수 완료

자료 조사 → 컨셉 → 시스템 → 진행 → 검증 → HTML. 검증에서 발견한 문제는 해당 기획을 소유한 단계로 돌아간다.

총괄 스킬은 $game-planning-workflow다. 단계마다 입력·출력·완료 기준을 인계하며, 변경된 자료에 영향을 받는 단계만 다시 검토한다.

조사와 독립 검수는 병렬화할 수 있다. 컨셉에 의존하는 규칙과 진행 설계는 순서대로 확정한다.

문서 검수 완료근거: 실제 관찰 기록

재사용하는 것은 기획 의도 → 상세 규칙 → 진행 설계 → 검증 근거 → 읽기 화면의 분리다. 원저자가 실제로 어떤 검색 순서로 기획했는지는 보존된 자료만으로 알 수 없다.

상류 원본 CSV와 생성기는 현재 미러에 없으므로 그 빌드가 실행되는지 검증한 것은 아니다.

단계별 스킬 상세

문서 검수 완료
1. 자료 조사와 근거
문서 검수 완료항목 링크

호출: $game-planning-research

입력: 아이디어·참고 URL·기존 자료·개발 제약

조사 질문을 먼저 정한다. 실제 관찰과 해석을 나누고, 채택할 근거와 보류할 이유를 기록한다.

산출물: 00-brief.md · sources.json · 01-research.md

완료 기준: 주요 선택에 쓸 수 있는 근거가 있고, 접근하지 못한 자료·상충 정보·미지수가 드러난다.

2. 핵심 재미와 컨셉
문서 검수 완료항목 링크

호출: $game-planning-concept

입력: 브리프·조사 결과·관찰 R

플레이어가 무엇을 판단하고 반복하며 어떤 감정을 얻는지 정의한다. 성공·실패·재시도와 MVP 범위를 연결한다.

산출물: 02-concept.md

완료 기준: 재미 가설, 핵심 선택, 한 판 흐름과 최소 범위가 서로 일치한다.

3. 시스템과 콘텐츠
문서 검수 완료항목 링크

호출: $game-planning-systems

입력: 컨셉·선택한 결정 D·기존 정본

입력, 상태, 조건, 효과, 피드백, 예외와 복구를 명세한다. 장르에 필요한 콘텐츠만 정의하고 수치의 단위와 근거를 남긴다.

산출물: 03-systems.md

완료 기준: 실제 구현자가 규칙을 해석할 수 있고 항목 ID·조합·경계 조건에 모순이 없다.

4. 학습과 진행 설계
문서 검수 완료항목 링크

호출: $game-planning-progression

입력: 핵심 루프·시스템 SYS·개발 범위

처음 배우는 것, 응용, 숙련, 회복의 흐름을 만든다. 선형 스테이지가 없으면 세션·튜토리얼·성장 구간으로 표현한다.

산출물: 04-progression.md

완료 기준: 각 진행 단위의 목적과 요구 판단, 콘텐츠 도입 순서와 다음 연결을 설명할 수 있다.

5. 모순 검수와 검증 계획
문서 검수 완료항목 링크

호출: $game-planning-validation

입력: 조사·컨셉·시스템·진행·실제 증거

문서의 모순과 가설을 검토하고 질문별 방법·성공 기준·근거·상태·수정 대상을 정한다. 실제 플레이 결과가 없으면 미실행으로 둔다.

산출물: 05-validation.md

완료 기준: 문서 검수 결과가 있고 실제 관찰, 계산, 설명용 예시와 검증 계획이 구분된다.

6. HTML 기획서 생성
문서 검수 완료항목 링크

호출: $front-game-planning-html

입력: 정본 문서·현재 검증 상태

원문에서 열람용 데이터를 만들고 정적 HTML로 빌드한다. 목차, 검색, 상세 펼침, 표, 근거와 상태를 제공한다.

산출물: portal.json · index.html

완료 기준: 직접 열기와 탐색이 동작하고 원문·표시 내용·미결정 상태가 일치한다.

자료에서 기획 결정까지

문서 검수 완료

S-01 출처 → R-01 관찰 → D-01 결정 → SYS-01/P-01 명세 → V-01 검증을 따라갈 수 있게 한다.

레퍼런스에서 짧은 세션을 관찰했다고 우리 게임도 같은 길이로 확정하지 않는다. 플레이어 선택을 분석하고 우리 제약에 맞는 가설을 만든 뒤 검증한다.

독창적인 아이디어는 새 가설로 표시하면 된다. 확인하지 않은 출처나 사람의 반응을 만들어 붙이지 않는다.

상태 관리와 다시 실행할 범위

문서 검수 완료

workflow.json은 단계별 입력 해시와 출력 경로, 결정 이력, 다음 행동을 남긴다. 재개할 때 이를 확인한다.

알 수 없는 수치는 null/미정으로, 실행하지 않은 측정은 미측정으로 남긴다. 0으로 채우지 않는다.

다른 프로젝트에서 시작하기

문서 검수 완료

$game-planning-workflow 새 모바일 퍼즐을 기획해줘. 세로 화면·한 손 조작·짧은 세션을 원하고 2인 팀이야. 제공한 자료와 공개 레퍼런스를 조사해 기획 문서와 로컬 HTML까지 만들어줘.

이 조건은 예시이며 새 게임의 기본값이 아니다. 새 게임의 아이디어, 제약, 갖고 있는 자료를 바꿔 넣으면 된다.

$game-planning-workflow 이 프로젝트의 workflow.json부터 확인하고 실패 후 재시작 규칙을 체크포인트 방식으로 바꿔줘. 영향받는 문서와 HTML도 갱신해줘.

$game-planning-validation 현재 기획의 모순과 미검증 가설만 점검해줘.

재사용 범위와 검증의 한계

문서 검수 완료

적 16종, 300단계, 10단계 단위 신규 도입, 격자 기반 점수식은 Avoid Ball 전용이다. 다른 게임에서는 장르와 목적에 맞는 진행 단위와 콘텐츠를 정의한다.

도식과 시뮬레이션은 시간·공간 관계를 설명해야 할 때만 추가한다. 설명용 애니메이션은 실제 충돌이나 사람의 재미를 검증하지 않는다.

게임 기획 Markdown이 정본이고 portal.json은 열람용 투영, index.html은 빌드 결과다. Markdown 변경을 자동 의미 분석하거나 백그라운드에서 감시하지는 않는다.

이 페이지는 워크플로우 설명 및 HTML 빌더 예제다. 신규 게임의 조사나 플레이테스트가 이미 완료됐다는 뜻은 아니다.
