문서 검수 완료

원작 분석과 신작 기획을 조사·작성·검수·HTML로 연결하는 7개 스킬의 사용 안내입니다. V3 사전에서 장르별 용어를 선택하고 실제 보고서 문장의 의미를 검수합니다. 프로젝트 사전과 STE-KO 문서 표면을 기본 적용하고 자동 탐지·의미 대조·수동 문체 검수를 실행합니다.

문서 준비 상태와 게임 검증은 별개입니다. 문서 검수 완료는 재미·밸런스·사업성의 실측 검증을 의미하지 않습니다.

검색 결과가 없습니다. 다른 단어로 검색해 주세요.

이 페이지와 시작 방법

문서 검수 완료

이 페이지는 harness-game-planning 저장소의 index.html입니다. README의 게임 기획 스킬 설치·조회·집필·검수 절차를 웹페이지로 읽는 안내 열람본입니다.

최신 내용은 README.md와 스킬 지침에서 확인합니다. portal.json은 표시 데이터, index.html은 기존 Python 빌더로 생성한 결과입니다.

저장소를 받은 뒤 아래 명령으로 로컬 서버를 실행하고 http://127.0.0.1:4174/index.html을 엽니다. macOS에서는 start.command를 실행해도 됩니다. GitHub에서 index.html을 클릭하면 소스가 표시됩니다.

git clone https://github.com/harness-subdev/harness-game-planning.git cd harness-game-planning python3 -m http.server 4174 --bind 127.0.0.1

skills/의 7개 폴더를 실제 Codex 스킬 설치 루트 아래 같은 이름으로 복사합니다. 기존 파일을 비교한 뒤 갱신하고 일곱 폴더의 상대 참조를 유지합니다. V3 사전과 조회 도구도 workflow 폴더와 함께 설치됩니다.

흐름 그림에는 별도 설치한 mermaid-diagrams, 추가 화면 검수에는 webapp-testing을 사용할 수 있습니다. 두 보조 스킬은 이 저장소에 포함되어 있지 않습니다.

v0.3.0에서 달라진 점

문서 검수 완료

기존 프로젝트 사전과 선택 V3 정의로 명칭과 개념 경계를 확인한 뒤 STE-KO 문서 표면으로 작성합니다.

작성 후 자동 탐지와 실제 문장의 용어 의미·수동 문체 대조를 수행하고 원문 수정·재검사로 닫습니다.

최종 검사기는 기존 workflow.json/05-validation.md의 검수 범위와 실제 입력 해시를 확인합니다. 누락·실행 실패·미실행·오래된 기록은 완료로 처리하지 않습니다.

STE-KO 지정 커밋 원본과 MIT 라이선스를 스킬에 함께 배포합니다. 자동 검사는 일부 패턴만 다루며 전역 답변 스킬은 설치하지 않습니다.

의미 버전은 0.3.0, HTML 입력 형식은 version: 1입니다. 기존 7개 스킬 이름과 빌더를 유지합니다.

기본 용어·문체 검수

문서 검수 완료

작성 전 사전 선택 → STE-KO 문서 작성 → 자동 탐지와 실제 의미·수동 문체 검수 → 원문 수정·재검사 → 기존 검수 기록/해시 확인으로 진행합니다.

작성 중에는 --lint-only를 사용합니다. 이것만으로 완료하지 않으며 실제 대조 후 최종 명령을 실행합니다. 사용자 지정 V3는 --domain-dictionary로 지정합니다.

python3 skills/game-planning-workflow/scripts/check_report_language.py PROJECT/01-research.md --glossary PROJECT/00-glossary.md --workflow PROJECT/workflow.json

검수 기록의 현재성 확인은 의미의 진실성을 기계가 증명한다는 뜻이 아닙니다. 표·인용과 문맥 규칙도 실제로 읽어야 합니다.

V3 장르 사전과 용어 선택

문서 검수 완료

보고서·기획 시작 시 사전 첫 HTML 주석의 JSON 메타데이터(schema=game-domain-dictionary-query/1)를 확인합니다. 대상의 조작·목표·진행을 실제 등록 장르·하위 유형과 대응시킵니다. 기능이나 행동을 새 하위 장르로 만들지 않습니다.

메타데이터 → 장르 대응 → 이름 정의 확인 → 필요한 전문어 조회 → 프로젝트 명칭 선택 → 본문 작성 → 의미 검수·수정 → HTML 투영으로 연결합니다.

확정 사전은 129개 노드·653행(이름 정의 153개 + 전문어 500개)·120개 번호형 출처를 보존합니다. workflow의 references/game-domain-dictionary-v3.md와 scripts/query_dictionary.py를 함께 설치합니다.

다음 명령은 저장소 루트 기준입니다. 설치 후에는 실제 설치된 workflow 스킬의 script 경로로 실행합니다. 도구는 파일을 내부에서 읽고 메타데이터 또는 선택 행만 출력합니다.

python3 skills/game-planning-workflow/scripts/query_dictionary.py --list python3 skills/game-planning-workflow/scripts/query_dictionary.py 1.2.1 --mode genre_names python3 skills/game-planning-workflow/scripts/query_dictionary.py 1.2.1 --mode terms python3 skills/game-planning-workflow/scripts/query_dictionary.py 1.2.1 1.23.2 --mode terms python3 skills/game-planning-workflow/scripts/query_dictionary.py 2.6 --mode terms --scope direct --key '런(run)'

복합 장르는 각각 명시적으로 선택합니다. ARPG(1.10.1)·시간관리(1.13.2)의 직접 전문어는 빈 결과를 유지합니다. 필요한 부모·공용·다른 장르 개념은 사용 목적과 별도 node/key를 정해 조회합니다. 등록되지 않은 ID나 범위에 없는 key는 오류입니다.

행의 정의·구별 기준·의미 차이·예문·ref를 확인해 대상·행동·결과에 맞는 명칭을 고릅니다. 반동과 탄퍼짐은 별개입니다. 예문의 반동 방향·크기나 런 초기화 조건은 작품 규칙 또는 신작 확정 설계의 근거가 아닙니다.

프로젝트 사전(기존 사전 또는 00-glossary.md)에 명칭·쉬운 정의·구별·원어·명칭 상태·작품 규칙 근거와 사전 node ID/key·ref·본문 사용 위치를 기록합니다. 사전 경로/해시·조회 범위·별도 참조·선택 이유는 기존 작업 기록에 남깁니다.

validation은 실제 사용 문장과 개념 경계를 대조하고 수정된 원문을 HTML에 넘깁니다. 내부 조회·검수 이력은 독자용 보고서나 HTML에 표시하지 않습니다. 사전 자체는 보고서 작업 중 재집필하지 않습니다.

원작 분석과 신작 기획의 실행 구조

문서 검수 완료

아이디어·기존 기획·레퍼런스 → game-planning-workflow 총괄 → V3 메타데이터·장르 대응·필요한 용어 선택 → 요청 목적에 맞는 조사·집필 → 용어 의미·내용·근거 검수 → HTML 생성·화면 확인으로 연결합니다.

원작 분석: research가 자료·장면·UI 조사와 보고서를 작성하고 필요한 concept/systems/progression 해석만 연결합니다. validation의 내용·출처·장면·용어 의미 대조 후 HTML로 이어집니다.

신작 기획: research → concept → systems → progression → validation → HTML 순으로 필요한 단계만 수행합니다. 근거·해석 문제는 조사/작성자에게, 규칙·진행 문제는 해당 정본 소유 단계에 돌아갑니다.

총괄은 범위·단계 선택과 작업 상태·재개를 관리합니다. 개별 스킬도 호출할 수 있으며 기존 사용자 결정·정본을 보존합니다.

원작 레퍼런스 보고서의 경로

문서 검수 완료

원작 보고서는 게임 개요 → 게임 메커니즘(아웃게임·인게임) → 핵심 설계 특징 → 참고자료와 조사 범위로 작성한다. 신작의 MVP·SYS/P/V·제작·시험 문서를 원작의 필수 산출물로 만들지 않는다.

research가 범위·명칭·질문을 정리하고 원자료·공개 실제 플레이 영상과 UI를 조사한다. 연결 Chrome으로 필요한 구간과 조건을 관찰하고 취득한 캡처의 최종 픽셀·시각을 대조한다.

캡처가 있으면 영상 시각·캡처·행동/변화 설명·직접 원영상 링크를 함께 배치한다. 캡처가 없으면 설명을 유지하고 영상 관찰, 캡처 미첨부 / 자료 설명 / 장면 미확인을 구별한다. 확인하지 못한 행동·시각은 관찰 사실로 쓰지 않는다.

필요한 경험·규칙·진행 해석만 concept/systems/progression으로 분기하고, 확인된 흐름 그림은 별도로 설치된 mermaid-diagrams로 연결한다. validation이 내용·출처·장면 대응을 대조한 뒤 front-game-planning-html이 표시 생성과 Chrome 검수를 맡는다.

제공 version 1 빌더는 이미지·Mermaid·더 깊은 중첩을 지원하지 않는다. 실제 원작 보고서는 필요한 표시를 지원하는 기존 렌더러 또는 HTML 요청 범위의 최소 보완을 선택한다. 이번 예시는 원작의 실제 캡처·그림 표시를 구현하거나 검수한 결과가 아니다.

신작 단계별 스킬 상세

문서 검수 완료
1. 자료 조사와 근거
문서 검수 완료항목 링크

호출: $game-planning-research

입력: 아이디어·참고 URL·기존 자료·개발 제약

조사 질문을 먼저 정한다. 실제 관찰과 해석을 나누고, 채택할 근거와 보류할 이유를 기록한다.

V3 메타데이터로 장르를 대응하고 필요한 전문어를 확인합니다. 정의 출처와 작품 규칙 근거를 구별해 프로젝트 사전·본문 위치와 조사 결과를 인계합니다.

산출물: 00-brief.md · sources.json · 01-research.md

완료 기준: 주요 선택에 쓸 수 있는 근거가 있고, 접근하지 못한 자료·상충 정보·미지수가 드러난다.

2. 핵심 재미와 컨셉
문서 검수 완료항목 링크

호출: $game-planning-concept

입력: 브리프·조사 결과·관찰 R

플레이어가 무엇을 판단하고 반복하며 어떤 감정을 얻는지 정의한다. 성공·실패·재시도와 MVP 범위를 연결한다.

선택 용어의 정의·구별을 확인해 핵심 경험과 반복·MVP를 설명합니다. 새 규칙은 신작 제안·프로젝트 정의·미정 상태로 구별합니다.

산출물: 02-concept.md

완료 기준: 재미 가설, 핵심 선택, 한 판 흐름과 최소 범위가 서로 일치한다.

3. 시스템과 콘텐츠
문서 검수 완료항목 링크

호출: $game-planning-systems

입력: 컨셉·선택한 결정 D·기존 정본

입력, 상태, 조건, 효과, 피드백, 예외와 복구를 명세한다. 장르에 필요한 콘텐츠만 정의하고 수치의 단위와 근거를 남긴다.

입력·상태·조건·효과를 명세하며 반동/탄퍼짐 같은 개념 경계를 유지합니다. 사전 예문을 실제 규칙으로 채택하지 않고 수치·예외는 설계 근거로 정합니다.

산출물: 03-systems.md

완료 기준: 실제 구현자가 규칙을 해석할 수 있고 항목 ID·조합·경계 조건에 모순이 없다.

4. 학습과 진행 설계
문서 검수 완료항목 링크

호출: $game-planning-progression

입력: 핵심 루프·시스템 SYS·개발 범위

처음 배우는 것, 응용, 숙련, 회복의 흐름을 만든다. 선형 스테이지가 없으면 세션·튜토리얼·성장 구간으로 표현한다.

런·세션·성장과 실제 콘텐츠 진행 단위를 구별합니다. 실패·종료·재시작 때 유지/초기화 조건을 해당 규칙 정본과 연결합니다.

다른 프로젝트에서 시작하기

문서 검수 완료

$game-planning-workflow 제공한 게임의 규칙과 진행을 조사해 원작 레퍼런스 보고서와 로컬 HTML로 만들어줘. 전체 구조와 상세 대상을 구분하고 자료·영상·UI 확인 범위를 밝혀줘. V3의 장르 이름과 필요한 전문어를 확인해 쓰고 본문 의미와 작품 규칙 근거를 검수해줘.

$game-planning-workflow 새 모바일 퍼즐을 기획해줘. 세로 화면·한 손 조작·짧은 세션을 원하고 2인 팀이야. 제공한 자료와 공개 레퍼런스를 조사해 기획 문서와 로컬 HTML까지 만들어줘.

$game-planning-workflow FPS와 로그라이트를 결합한 신작 기획을 작성해줘. 각 장르 범위를 명시하고 반동과 탄퍼짐을 구별해줘. 런은 공용 정의를 별도 조회하고 종료·유지 조건은 신작 설계로 구분해줘. 미확정 규칙은 제안 또는 미정으로 남겨줘.

$game-planning-workflow 이 프로젝트의 workflow.json부터 확인하고 실패 후 재시작 규칙을 체크포인트 방식으로 바꿔줘. 영향받는 문서와 HTML도 갱신해줘.

$game-planning-validation 현재 기획의 모순과 미검증 가설만 점검해줘.

위 조건은 예시이며 새 게임의 기본값이 아닙니다. 실제 아이디어·제약·자료로 바꿔 입력합니다.

재사용 범위와 검증의 한계

문서 검수 완료

적 16종, 300단계, 10단계 단위 신규 도입, 격자 기반 점수식은 Avoid Ball 전용이다. 다른 게임에서는 장르와 목적에 맞는 진행 단위와 콘텐츠를 정의한다.

도식과 시뮬레이션은 시간·공간 관계를 설명해야 할 때만 추가한다. 설명용 애니메이션은 실제 충돌이나 사람의 재미를 검증하지 않는다.

게임 기획 Markdown이 정본이고 portal.json은 열람용 투영, index.html은 빌드 결과다. Markdown 변경을 자동 의미 분석하거나 백그라운드에서 감시하지는 않는다.

이 페이지는 워크플로우 설명 및 HTML 빌더 예제다. 신규 게임의 조사나 플레이테스트가 이미 완료됐다는 뜻은 아니다.

v0.1.0에서는 원작·신작 계약과 조사·작성·검수·HTML 인계를 정리하고 고정 횟수의 반복 인터뷰·grill 관문을 제거했다. 7개 스킬 이름과 기존 빌더 런타임을 유지했다.

VERSION의 0.2.0은 의미 버전이고 정확한 Git 커밋 SHA는 빌드 식별자다. portal.json의 version: 1은 입력 형식 버전이다. 다음 버전은 VERSION과 CHANGELOG의 해당 변경 내역을 수동으로 갱신하고 표시 버전을 맞춘 뒤 자체 점검·HTML 빌드를 실행한다.

v0.2.0의 기존 게시 기록은 조회·지침·로컬 빌드 검증입니다. 최신 README를 반영한 이번 안내 페이지 갱신의 화면 확인 범위는 VERIFICATION.md에 별도로 기록합니다. 실제 작품·영상 관찰·캡처·사람 플레이테스트와 안내 페이지의 화면 확인은 구별합니다.

제공된 Avoid Ball 분석 기록

문서 검수 완료근거: 자료 근거 있음

아래는 이전에 제공된 자료·미러의 분석 기록이다. 재사용하는 것은 기획 의도·상세 규칙·진행 설계·검증 근거·읽기 화면의 분리다. 원저자의 실제 검색 순서는 자료만으로 알 수 없다. v0.1.0 게시 작업에서 원사이트를 새로 관찰하지 않았다.

당시 원본 README는 구조 점수를 v2/10개 항목이라고 설명하지만 campaign 데이터에는 v3 294단계와 v4 6단계가 섞여 있다고 기록됐다. 자료 설명과 정본의 적용 범위·버전을 대조해야 한다.

당시 미러에는 상류 원본 CSV와 생성기가 없어 그 원본 빌드 실행 여부는 검증하지 못했다.
